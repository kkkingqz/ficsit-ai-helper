# Чек-листы спайков этапа 1 (P-7, #32)

Настоящий документ устанавливает объективные, проверяемые критерии завершения для каждого исследовательского спайка этапа 1 (ARCHITECTURE.md §13, PLAN-v0.1.md §5.2).

> [!IMPORTANT]
> **Правило 2 KICKOFF:** Работа считается готовой по чек-листу Gf2 из P-7, а не по субъективному ощущению. Чек-лист существует до начала работы над спайком. Если спайк опровергает выбранное решение, принимается документированный **fallback** через ADR до начала зависящих работ.

## 1. Spike S1 · Терминал, хост, модуль

- **Сроки:** недели 2–3 · **Ведущий:** Gf · **Ревью:** Co
- **Задача в milestone:** [#9 (S1)](https://github.com/kkkingqz/ficsit-ai-helper/issues/9)
- **Контракт интерфейсов:** [`docs/interfaces/screen-host-and-module.md`](../../docs/interfaces/screen-host-and-module.md)

### Чек-лист готовности S1

#### 1.1. Класс терминала и игровая интеграция (Gf)
- [ ] Терминал реализован как строительный объект (`AFicsitAITerminal` в `GameFacade/`), требующий подключения к электросети.
- [ ] Потребление энергии зафиксировано на уровне **10 MW** при работе.
- [ ] Рецепт постройки и схема зарегистрированы через `UModContentRegistry` (ADR-027).
- [ ] Меш-заготовка терминала содержит плоскую поверхность экрана с соотношением сторон **16:9** (ADR-030).
- [ ] Взаимодействие: нажатие клавиши `E` при взгляде на терминал открывает интерфейс хоста.

#### 1.2. Хост и модули (Gf, Co)
- [ ] В `FicsitAIApi` объявлены чистые интерфейсы `IFicsitAIScreenHost`, `IFicsitAIScreenModule`, контекст `FFicsitAIScreenContext` и поверхность `IFicsitAIScreenSurface` (без типов UMG, SML и игры).
- [ ] Реализованы два тестовых экранных модуля (например, тестовые Notes и Dashboard-заглушка) в `FicsitAIUI`.
- [ ] Хост терминала открывает оба тестовых модуля и поддерживает переключение между ними.
- [ ] **Критерий переиспользования (AC-14):** Те же два модуля без единого изменения их кода открываются во втором (автономном тестовом) хосте.
- [ ] Модули в `FicsitAIUI` не имеют ссылок на класс терминала (проверяется инвариантом CI `check-invariants.sh` №5).

#### 1.3. Состояния хоста и жизненный цикл (Gf, Co)
- [ ] **Состояние «Нет питания» (NoPower):** При отсутствии подключения к электросети или срабатывании предохранителя нажатие `E` открывает статус «нет питания» вместо модулей; активный открытый модуль при отключении питания сохраняет состояние через `SavePersistentState`, вызывает `OnDetach` и закрывается.
- [ ] **Восстановление состояния:** Повторное открытие терминала восстанавливает последнее состояние открытого модуля через `RestorePersistentState`.
- [ ] **Горячие клавиши и перехват Esc (`HandleBackAction`):** Модуль объявляет действия через `GetHotkeyHints()`, хост отображает актуальные привязки клавиш Enhanced Input (ADR-027). При нажатии клавиши `Esc` хост опрашивает открытый модуль через `IFicsitAIScreenModule::HandleBackAction()` (Gs-17):
  - **Исход 1 (`HandleBackAction() == true`):** Модуль сам перехватил действие (например, отменил потоковый ответ модели или закрыл вложенное модальное окно) — экран остаётся открытым, хост терминал не закрывает;
  - **Исход 2 (`HandleBackAction() == false`):** Действие модулем не перехвачено — хост закрывает терминал и возвращает управление игроку.

#### 1.4. Идентификатор сохранения и мультиплеер (Gf)
- [ ] `saveId` мода генерируется при первом запуске через `AModSubsystem` + `IFGSaveInterface` и сохраняется в `.sav`.
- [ ] `saveId` остаётся неизменным при переименовании файла сохранения и ротации автосохранений (MODULES A6).
- [ ] **Инертный режим (Inert):** Мод объявляет `RequiredOnRemote = true`; сессия, запущенная как мультиплеерная, переводит терминал в инертный режим с уведомлением игрока.
- [ ] Событие подключения удалённого игрока (или fallback-опрос состава игроков) переводит хост в `HostState::Inert`.
- [ ] Действие взаимодействия с терминалом появляется в штатном меню переназначения клавиш игры (Enhanced Input, MODULES A5).

**Критерий завершения S1:** Модуль открывается в AI Terminal и в тестовом хосте без изменений своего кода; терминал потребляет 10 MW; `saveId` персистентен; «нет питания» и инертность работают; инварианты CI зелёные.

## 2. Spike S2 · Адаптер и канал к моду

- **Сроки:** недели 2–4 · **Ведущие:** Co2, Co · **Ревью:** Co (контрактная поверхность), Gs (код Co)
- **Задача в milestone:** [#10 (S2)](https://github.com/kkkingqz/ficsit-ai-helper/issues/10)
- **Контракт публичного API:** [`docs/interfaces/public-api-v0.md`](../../docs/interfaces/public-api-v0.md)

### Чек-лист готовности S2

#### 2.1. Адаптер сайдкара (Co2)
- [ ] Адаптер запускается на Node 22 (TypeScript) и слушает строго `127.0.0.1` (AC-12).
- [ ] Авторизация: токен доступа генерируется локально и передаётся в строке запроса `MCP_URL` (`?token=...`).
- [ ] Foreman успешно подключается к адаптеру как к единственному MCP-серверу (ADR-012).
- [ ] Автоматический вход в локальный Foreman: адаптер создаёт сессию Better Auth без интерактивного ввода пароля игроком.
- [ ] Сопоставление сохранения: `saveId` мода связывается с playthrough Foreman; `savePath` в API мода не используется (ADR-014).
- [ ] Чат API для мода реализован поверх `POST /api/playthroughs/:id/chat` с поддержкой потокового ответа (SSE), отмены запроса и чтения истории.
- [ ] Системный промпт подключается через `SYSTEM_PROMPT_PATH`; проверена отдача числа использованных токенов.
- [ ] **Белый список инструментов:** Адаптер скрывает собственные инструменты `sf-mcp` от модели, выставляя только белый список инструментов мода.

#### 2.2. Исходящий канал связи из мода (Co)
- [x] **Выбор транспорта:** Модуль `WebSockets` отсутствует в поставке игры, канал связи строится на модуле `HTTP` движка (ARCHITECTURE §3.3; Co-33).
- [ ] **Сетевой запрос на loopback под Proton:** Запрос из мода через `HTTP` движка на `http://127.0.0.1:<port>` под Proton (Wine WinHttp) успешно проходит без блокировок безопасности («небезопасный запрос»).
- [ ] **Потоковое чтение (Chunked Streaming):** Потоковое чтение тела ответа адаптера (`/mod/stream`) в моде работает инкрементально: строки/события поступают по мере отправки, а не буферизуются целиком до закрытия соединения.
- [ ] Канал связи инициализируется **из мода наружу** (мод подключается к адаптеру на `127.0.0.1`, входящих сокетов в моде нет — ADR-012). Маршруты `/mod/stream` и `/mod/send` обслуживаются тем же слушателем адаптера с авторизацией по токену в заголовке (Co2-13).
- [ ] Обработка сетевых сообщений выполняется строго **вне GameThread** (в фоновом потоке / worker thread).
- [ ] Реализовано автоматическое переподключение (reconnect) с экспоненциальной задержкой при перезапуске адаптера; сообщения адресуются по порядковому номеру, а не по соединению.

#### 2.3. Сквозной вызов и производительность (Co, Co2)
- [ ] Сквозной вызов: сообщение пользователя в чате → LLM генерирует tool call `query_metric` → адаптер передаёт вызов в мод по каналу → мод отдаёт заглушку метрики → модель формирует текстовый ответ с цифрой.
- [ ] Во время приёма/отправки сообщений и tool call кадровое время игры (FPS) не проседает (дельта GameThread $\le 0.5$ мс).
- [ ] При остановленном адаптере игра не зависает и не крашится (проверка устойчивости).

**Критерий завершения S2:** Foreman видит инструменты мода; вызов инструмента доходит по исходящему каналу; ответ собирается вне GameThread; FPS не проседает.

## 3. Spike S3 · Каталог, телеметрия, линии

- **Сроки:** недели 2–4 · **Ведущий:** Gs · **Вместе с:** Gf, Gf2 · **Ревью:** Co
- **Задача в milestone:** [#11 (S3)](https://github.com/kkkingqz/ficsit-ai-helper/issues/11)

### Чек-лист готовности S3

#### 3.1. Каталог контента и рецептов (Gs)
- [ ] Слой данных SBC свендорен в `third_party/sbc/` с сохранением оригинальной лицензии MIT и файлом описания изменений (ADR-027, R-09). Код SBC не копипастится в модули проекта.
- [ ] `CatalogProvider` извлекает перечень предметов, построек и рецептов из `UModContentRegistry`.
- [ ] Корректно определяются статусы разблокировки рецептов и числовые параметры из игровых подсистем (`AFGRecipeManager` и др.).
- [ ] Проверена работа каталога на сохранении с модом, добавляющим альтернативные рецепты: модовые рецепты определяются штатно, статус разблокировки корректен.
- [ ] Перевод единиц жидкостей ($1\ \text{м}^3 = 1000$ внутренних единиц) выполняется строго один раз на границе `CatalogProvider` (§5.6).

#### 3.2. Индекс построек и телеметрия (Gs, Gf)
- [ ] Реализован индекс построек, обновляемый по событиям строительства и демонтажа.
- [ ] Каркас телеметрии (`TelemetrySampler`) реализован с нарезкой сбора по кадрам (time-slicing) без блокировки GameThread.
- [ ] Сборщики электросетей (Gs): общее производство, потребление, ёмкость, максимум потребления, статус предохранителя.
- [ ] Сборщики генераторов, батарей и загрузки машин (Gf на каркасе Gs).
- [ ] Идентификатор `buildingId` проверен на трёх тестовых сохранениях (P-5): идентификаторы стабильны между перезапусками сессии.
- [ ] Прототип режима привязки построек к линии: ручное добавление/удаление машин в именованную линию (ADR-019).

#### 3.3. Замеры бюджета и сверка метрик (Gf2, Gs)
- [ ] Проведены замеры стоимости выборки телеметрии на 3 тестовых сохранениях по протоколу P-7.
- [ ] Суммарное время выборки телеметрии укладывается в бюджет GameThread ($\le 2.0$ мс на кадр при нарезке).
- [ ] **Замер стоимости записи состояния на машину (решения King 11.11.2026, Co-45):** Измерена стоимость записи пользовательских данных/тегов на постройку в GameThread на Save B (`SetCustomData` / структура состояния, бюджет $\le 0.05$ мс).
- [ ] **Замер локального обхода связей от одной машины (решения King 11.11.2026, Co-45):** Измерена стоимость локального графового обхода соединений конвейеров/труб для выявления кандидатов производственных линий (бюджет $\le 0.5$ мс).
- [ ] Каталог метрик v0.1 составлен и сверен с перечнем 71 метрики FRM Companion: для каждой метрики зафиксированы `id`, единица измерения, класс стоимости и частота опроса.
- [ ] Сформулировано измеримое математическое определение «стабильности энергосети».

**Критерий завершения S3:** Каталог читает vanilla и modded рецепты; статус разблокировки верен; телеметрия на фабрике в несколько тысяч построек укладывается в бюджет GameThread; `buildingId` стабилен.

## 4. Spike S5-lite · Поставка сайдкара для альфы

- **Сроки:** недели 4–5 · **Ведущие:** Co2, Gf · **Вместе с:** Gf2 · **Ревью:** Co
- **Задача в milestone:** [#13 (S5-lite)](https://github.com/kkkingqz/ficsit-ai-helper/issues/13)

### Чек-лист готовности S5-lite

#### 4.1. Сборка архива (Co2)
- [ ] Сформирован самодостаточный zip-архив сайдкара без Docker и без установщика.
- [ ] Состав архива:
  - Портативный Node.js 22;
  - Скомпилированный `ff-server` (Foreman);
  - MCP-сервер `sf-mcp`;
  - Адаптер сайдкара;
  - Движок Prisma для SQLite и предсозданная база данных;
  - Скрипт/лаунчер запуска (`start.bat` / `start.sh`).
- [ ] Архив собирается в двух раскладках: Linux (для машины разработки) и Windows (для закрытой альфы).
- [ ] Windows-архив успешно протестирован под wine на машине команды.

#### 4.2. Безопасность и автоматизация запуска (Co2, Gf)
- [ ] **Инвариант брандмауэра (AC-12):** Все процессы сайдкара (`HOST`, `MCP_HTTP_HOST` и адаптер) настроены строго на `127.0.0.1`. Прослушивание `0.0.0.0` запрещено.
- [ ] Лаунчер при первом старте генерирует необходимые секреты и спрашивает у пользователя только выбор провайдера (`LLM_PROVIDER`, `LLM_BASE_URL`) и API-ключ. Правка текстовых конфигурационных файлов игроком не требуется.
- [ ] Мод запускает сайдкар в фоновом режиме при старте игры и останавливает его при выходе, если запускал сам (Gf).

#### 4.3. Верификация пилотным тестером (Gf2, Пилотный тестер)
- [ ] Подготовлен чек-лист для внешнего пилотного тестера на чистой Windows (ADR-033, R-27).
- [ ] Тестер подтверждает: при распаковке и запуске **брандмауэр Windows не запрашивает разрешений** на открытие сетевых портов.
- [ ] Время от распаковки до первого ответа модели в чате — в пределах целевого времени (< 5 минут).

**Критерий завершения S5-lite:** Критерий V-08 достижим: чистая установка от распаковки до первого ответа без правки конфигов, кроме ключа; брандмауэр Windows молчит.

## 5. Spike S6 · Экраны вне игры и источники данных

- **Сроки:** недели 3–5 (после ворот W) · **Ведущие:** Co2, Gf2, Co · **Ревью:** Co
- **Задача в milestone:** [#12 (S6)](https://github.com/kkkingqz/ficsit-ai-helper/issues/12)

### Чек-лист готовности S6

#### 5.1. Разделение архитектурных слоёв (Co, Gf2)
- [ ] Модуль `FicsitAIUI` компилируется и компонуется без включения заголовков игры (`FactoryGame`) и `SML` (проверяется инвариантом CI №2).
- [ ] При выборе ветки UMG: проект Screen Lab открывается на стандартном Unreal Engine 5.6 без модификаций Coffee Stain (R-22).
- [ ] При выборе ветки Веб (ADR-032): экраны открываются в обычном браузере через Vite/dev-сервер с горячей перезагрузкой (HMR).

#### 5.2. Сменные источники данных (Co2, Gf2)
- [ ] Публичный API мода поддерживает работу поверх сменного источника данных (ADR-025): Live, Save, Recording, Fixture. Каждое значение помечается атрибутом источника (`source`).
- [ ] **Источник Save (Co2):** Адаптер разбирает файл `.sav` с помощью пакетов Foreman (`sf-save-data`, `sf-flow`) и отдаёт снимок данных через API без запуска игры.
- [ ] **Источник Recording (Gf2):**
  - Согласован формат потоковой записи API-событий в формате JSONL.
  - Реализован проигрыватель записей с поддержкой паузы, перемотки и изменения скорости (1x, 2x, 5x).
- [ ] **Наборы Fixture (Gf2):**
  - Подготовлен набор эталонных фикстур в `fixtures/`:
    1. Пустая фабрика (начало игры);
    2. Большая фабрика (высокая нагрузка);
    3. Аварийный режим: нет питания;
    4. Инертный режим: мультиплеерная сессия;
    5. Сайдкар недоступен.
- [ ] Экран «Статистика» успешно открывается вне игры на источниках Fixture, Save и Recording.

**Критерий завершения S6:** Модуль `FicsitAIUI` собирается без заголовков игры; экран открывается вне игры на Fixture и снимке `.sav`; запись Recording воспроизводится с перемоткой.
