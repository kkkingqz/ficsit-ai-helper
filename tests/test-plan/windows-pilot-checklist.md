# Чек-лист для пилотного тестера на Windows (AC-12, V-08)

## 1. Паспорт проверки и контекст

- **Назначение:** Единственная Windows-машина проекта находится у внешнего пилотного тестера (ADR-033, R-27). Разработчики мода работают на Linux под Proton. Проверки на чистой Windows с установленной лицензионной версией Satisfactory выполняет пилотный тестер по настоящему чек-листу.
- **Сроки проведения проверки:**
  1. **Резервная проверка Spike S8 (неделя 3):** проводится только в том случае, если тестирование встроенного браузера BLUI под Proton выявит непреодолимый сбой Wine/DXVK.
  2. **Обязательная приёмка поставки сайдкара (недели 5 и 8):** проверка архива сайдкара и установщика альфы не позднее чем за 3 дня до ворот G2 (R-27). Без положительного отчёта тестера условие ворот G2 невыполнимо.

## 2. Чек-лист проверки чистого развёртывания (Критерий V-08 / AC-12)

### Шаг 1. Подготовка стенда
- [ ] Тестовая машина работает под управлением чистой Windows 10 или Windows 11 (64-bit).
- [ ] Установлена актуальная версия Satisfactory (Steam или Epic Games Store).
- [ ] Установлен Satisfactory Mod Manager (SMM).
- [ ] Docker, Node.js или другие инструменты разработки на машине **не установлены** (проверка для обычного игрока).
- [ ] Брандмауэр Windows (Windows Defender Firewall) работает в стандартном режиме с включёнными уведомлениями.

### Шаг 2. Установка мода через SMM
- [ ] В SMM устанавливается мод `FicsitAI`.
- [ ] SMM автоматически подтягивает зависимость `FicsitAIWebRuntime`.
- [ ] Установка завершается без ошибок; моды отображаются активными в профиле SMM.

### Шаг 3. Распаковка архива сайдкара
- [ ] Архив `ficsitai-sidecar-win64.zip` скачивается и распаковывается в стандартную пользовательскую папку (например, `C:\Games\FicsitAI\sidecar` или `Downloads`).
- [ ] В папке отсутствуют сложные инструкции: присутствует файл запуска `start.bat` и краткий `README.txt`.

### Шаг 4. Первый запуск и брандмауэр (Критический пункт AC-12)
- [ ] Запускается `start.bat`.
- [ ] **КРИТИЧЕСКИЙ ПРОВЕРОЧНЫЙ ПУНКТ:** Брандмауэр Windows **НЕ показывает всплывающее окно** с запросом «Разрешить приложению доступ к сети» (ни для `node.exe`, ни для `ff-server.exe`, ни для других процессов).
  > *Пояснение: все внутренние сервисы мода и сайдкара слушают исключительно петлевой интерфейс `127.0.0.1`, что исключает сетевые предупреждения безопасности.*
- [ ] Консоль или стартовое окно лаунчера запрашивает у пользователя:
  1. Выбор LLM-провайдера (OpenAI, Anthropic, OpenRouter или кастомный адрес);
  2. Ввод API-ключа.
- [ ] Никакого ручного редактирования `.env`, `config.json` или работы с базами данных от пользователя не требуется.
- [ ] После ввода ключа лаунчер сообщает о готовности и переходит в режим ожидания игры.

### Шаг 5. Запуск игры и проверка сквозного пути
- [ ] Игра запускается через SMM или напрямую.
- [ ] Загружается тестовое или рабочее сохранение.
- [ ] В меню строительства возводится AI Terminal, подключается к электросети (10 MW).
- [ ] По нажатию `E` открывается интерфейс терминала:
  - Экран «Статистика» отображает живые графики и показатели текущей фабрики;
  - Экран «Чат с ИИ» показывает статус готовности помощника.
- [ ] В поле чата вводится контрольный вопрос (например: *«Сколько энергии производит фабрика?»*).
- [ ] Модель успешно возвращает потоковый текстовый ответ с корректными числами текущей энергосети.
- [ ] Время от начала распаковки архива до получения ответа модели составляет менее **5 минут**.

### Шаг 6. Завершение работы и очистка процессов
- [ ] Выход из игры через главное меню.
- [ ] Процессы сайдкара корректно завершают работу (либо закрываются лаунчером по выходу из игры).
- [ ] В Диспетчере задач Windows (Task Manager) отсутствуют зависшие «зомби»-процессы `node.exe`, `ff-server.exe` или субпроцессы CEF.
