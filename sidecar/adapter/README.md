# `adapter` — адаптер сайдкара

Тонкая прослойка между Foreman и модом. Для Foreman адаптер — **единственный `MCP_URL`**; для мода — точка входа чата и инструментов. Foreman не форкается и не патчится (ADR-012): всё, что расходится, гасится здесь.

## Что уже есть (P-3, [#4](https://github.com/kkkingqz/ficsit-ai-helper/issues/4))

Каркас, на который навешивается S2:

- слушатель **только на петле** — не-loopback адрес не предупреждение, а отказ запуска (`src/config.ts`);
- проверка токена из query `MCP_URL` постоянным по времени сравнением;
- MCP-эндпоинт `POST /mcp` на Streamable HTTP, **без управления сессиями**: на каждый запрос свой сервер и транспорт (так требует SDK в stateless-режиме);
- `GET /health` — версия, `apiVersion`, адреса Foreman и `sf-mcp`, состояние канала мода;
- логи с вычищенными секретами: токен, ключ провайдера в строке запроса, `x-anthropic-api-key`, `Bearer`, `sk-…` (`src/log.ts`). Адрес провайдера пишется без строки запроса целиком: ключ ездит именно там, и списка имён параметров для этого мало (ревью Gs-11);
- нормализатор ответов провайдера (ADR-034) — отдельный слушатель на петле **в этом же процессе**, подробности в [`../launcher/README.md`](../launcher/README.md);
- **переходы по `Location` не выполняются.** `fetch` по умолчанию идёт за редиректом и повторяет наши заголовки, а среди них ключ провайдера: `303` на `POST` уводил запрос с ключом на другой порт, и второй сервер его получал (ревью Gs-14). Спецификация снимает при смене origin только `Authorization`, про `x-goog-api-key` она не знает. Любой `3xx` с `Location` — отказ `502`: адрес провайдера задаётся локально, и редирект значит, что настройка указывает не туда.

**Инструменты идут насквозь из `sf-mcp`, кроме скрытых белым списком** (ниже). Своих инструментов адаптер не пишет: они придут из реестра операций, описания генерируются там (ARCHITECTURE §7.5, правило 2). Пустой список оставить нельзя: системный промпт обещает модели инструменты игровых данных, и с пустым списком ход обрывался без ответа. Поэтому `tools/list` и `tools/call` проксируются в `sf-mcp` (`src/upstream.ts`).

Граница доверия §7 при этом видна в коде, а не только на словах: набор `MOD_TOOL_NAMES` в `src/index.ts` отделяет инструменты мода от проброшенных. В v0 он пуст, но проброс через него не проходит — вызов имени из этого набора до `sf-mcp` не доходит, и `sf-mcp` не может занять имя инструмента мода.

## Вход в Foreman и сохранения (S2, [#10](https://github.com/kkkingqz/ficsit-ai-helper/issues/10))

У Foreman весь `/api/*` закрыт Better Auth, а спрашивать логин у игрока неоткуда (V-08: от распаковки до первого ответа без правки конфигов, кроме ключа). Поэтому адаптер заводит себе локальный аккаунт при первом запуске и входит сам (`src/foreman.ts`).

- **Cookie сессии на диск не пишется** — только в памяти процесса. Иначе рядом с базой появился бы второй файл с действующим секретом; цена — один лишний вход при перезапуске. Пароль лежит в файле аккаунта с правами 600 и в лог не попадает.
- **`Origin` обязателен.** Better Auth отвечает `403 MISSING_OR_NULL_ORIGIN` на запрос без этого заголовка: защита от межсайтовых запросов написана для браузера, а `fetch` в Node ничего не подставляет. Адаптер шлёт тот же адрес, на который и обращается, — `ff-server` доверяет `Origin`, host которого совпадает с адресом запроса. Защиту это не ослабляет: она про чужие страницы, а адаптер страницей не является.
- **Сессия истекла — вход заново и один повтор запроса**, а не ошибка моду.
- **Известная дыра: файл аккаунта потерян, а база осталась.** Тогда вход даёт `401`, регистрация — `422` (пользователь занят), и сайдкар не войдёт, пока пользователя не убрать из базы Foreman. Текст ошибки про «удалите файл аккаунта» в этом случае не помогает. Чинится это не правкой текста: нужен или другой адрес при занятом (и тогда прежние разговоры остаются у старого пользователя), или перенос пароля в тот же файл, что и базу, одним целым. Решать это в v0.1 незачем — обе части лежат в одном каталоге данных и теряются вместе, — но записать, пока помню, стоит.
- **Сохранение → playthrough считается, а не хранится.** Своего хранилища для этой связи нет и быть не должно: данные разговора живут в базе Foreman (§10). Идентификатор playthrough — `fa-` плюс половина отпечатка `saveId`, и он же передаётся Foreman при создании: Foreman принимает клиентский идентификатор из латиницы, цифр, дефиса и подчёркивания, а имя сессии игры не ограничено ничем. Пути к файлу `.sav` сайдкар не передаёт — файлы остаются делом Foreman (`SAVE_DATA_DIR`).

## API чата для мода (S2, [#10](https://github.com/kkkingqz/ficsit-ai-helper/issues/10))

Поверх `POST /api/playthroughs/:id/chat` Foreman, который отвечает SSE. Токен — в заголовке `Authorization: Bearer …`: обе стороны канала наши (§13), строка запроса остаётся только у Foreman, чей MCP-клиент заголовков не шлёт.

| Маршрут | Что делает |
|---|---|
| `POST /mod/saves/:saveId/chat` | ход чата. Тело — `{"message": "…", "saveName": "…"}`. Ответ — поток кадров |
| `POST /mod/saves/:saveId/chat/cancel` | отмена. Тело — `{"turnId": "…"}`; `202`, если ход был, `404` — если нет, `409` — если идёт другой |
| `GET /mod/saves/:saveId/history?limit=50` | последние сообщения разговора; `limit` до 500 |

Мод говорит **идентификатором сохранения**, а не playthrough: playthrough вычисляется (выше) и заводится при первом обращении, в том числе на запрос истории.

**Формат наружу — строчный JSON, не SSE.** Транспорт канала выбран в ARCHITECTURE §13: модуль `HTTP` игры с потоковым чтением тела, «построчный JSON». Разбора SSE у мода нет, и заводить его ради одного маршрута — лишний парсер в игровом процессе. Одна строка — один объект `{"event": …, "data": …}`; события `accepted`, `text`, `tool_use`, `work_order`, `done`, `error`, `cancelled` и `ping`. Сборка — одной функцией `encodeFrame` (`src/stream.ts`): если документ протокола канала потребует другой конверт, меняется она.

- `accepted` приходит первым и несёт `turnId` — им же отменяют.
- `ping` раз в 15 секунд: цикл инструментов может молчать десятками секунд, а тишина в канале неотличима от обрыва.

**Отмена — наша, у Foreman её нет вообще** (ни `AbortSignal`, ни `res.on('close')` в его маршруте; проверено по исходникам 12.11.2026). Мод перестаёт получать кадры немедленно, но **соединение к Foreman не рвётся, а дочитывается**, и следующий ход ждёт, пока это закончится (до 30 секунд, дальше `409 turn_draining`).

Так сделано не из вежливости к Foreman. Сначала адаптер обрывал запрос — и живая проверка показала, чем это кончается: пока брошенный ход дописывал ответ, игрок задал следующий вопрос, и история легла в порядке «вопрос — вопрос — ответ — ответ». Foreman пишет сообщение игрока до начала потока, а ответ — после, и разорванное соединение этого не отменяет. Поэтому ход остаётся занятым до конца; обычно это секунды (в живой проверке — 1,4 с).

Что отмена **не** делает: ход всё равно доигрывается, токены провайдера за него потрачены, ответ попадает в историю. Экрану чата это надо показать («ответ дописан в истории»), иначе игрок увидит противоречие.

**Один ход на сохранение.** Второй запрос получает `409 turn_in_progress` с идентификатором идущего: Foreman дописывает сообщение игрока до начала потока, так что два хода разом перемешали бы разговор.

**Число токенов Foreman не отдаёт** (вопрос S2, ARCHITECTURE §5). В потоке чата его нет: события только `text`, `tool_use`, `work_order`, `done`, `error`. В базе — нет. Единственное место, где оно появляется, — отладочная строка лога провайдера Anthropic (`llm/anthropic.ts`); на нашем пути (Gemini через OpenAI-совместимый эндпоинт) нет и её, потому что `stream_options.include_usage` Foreman не запрашивает. Значит, по §5 строка состояния ассистента числа токенов в v0.1 не показывает. **Правка Foreman для этого не нужна:** нормализатор (ADR-034) уже стоит на пути к провайдеру и может запросить `usage` сам, не трогая ответ, который получает Foreman. Это отдельное решение — вынесено вопросом Co2-25, в этой работе не делалось.

## Белый список и свой системный промпт (S2)

Модель видит инструменты `sf-mcp`, **кроме скрытых** (`src/whitelist.ts`). Скрытые нельзя просто не показать в `tools/list`: модель зовёт инструменты и по памяти о промпте, поэтому вызов скрытого имени получает отказ с причиной, а не проброс.

Скрыты тринадцать инструментов чтения загруженного `.sav`. Причина не «на будущее», а сегодняшняя ошибка: playthrough адаптера сохранения не несёт (`savePath` мы не передаём и не будем — §10), а без него `sf-mcp` берёт склад по умолчанию из `SAVE_FILE_PATH`. У разработчика это чужая игра, у игрока — отсутствующий файл: в первом случае модель уверенно расскажет про чужой мир, во втором ход сорвётся на ошибке инструмента. Живое состояние придёт от мода (V-3), и тогда эти имена останутся скрытыми уже по §3.3.

**Список — запрет, а не разрешение.** Разрешать поимённо строже, но тогда новый инструмент `sf-mcp` после обновления Foreman молча исчезал бы из чата, а мы узнавали бы об этом от игрока. Незнакомое имя проходит и попадает в `tools/list`, то есть становится видно нам.

Расчётные инструменты (`ingredient_tree`, `full_production_line`, `total_raw_inputs`, `compare_alternates`) §3.3 тоже называет скрываемыми, но в v0.1 они видны: замены им — `compute_plan` и реестр операций — ещё нет, и спрятать их сейчас значит получить ассистента, который считает по памяти. Прячутся вместе с реестром; расхождение §3.3 с таблицей вех §13 (белый список там отнесён к Milestone 2) вынесено вопросом Co2-24.

**Промпт правится только вместе со списком.** Свой промпт — `third_party/foreman/SYSTEM_PROMPT.md` (изменённая копия файла Foreman, Apache-2.0, перечень правок рядом), подключается лаунчером через `SYSTEM_PROMPT_PATH`. Штатный промпт обещает скрытые инструменты поимённо, и обещание несуществующего заканчивается ходом без ответа. Согласие промпта со списком проверяет `test/whitelist.test.ts`: он читает тот же файл и тем же разбором, что Foreman.

## Окружение

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ADAPTER_HOST` | `127.0.0.1` | только петля; другое значение — отказ запуска |
| `ADAPTER_PORT` | `8730` | порт адаптера |
| `ADAPTER_TOKEN` | — | **обязателен**, не короче 16 символов; генерирует лаунчер, в репозитории не лежит |
| `FOREMAN_BASE_URL` | `http://127.0.0.1:8724` | куда ходить за чатом и playthrough |
| `SF_MCP_URL` | `http://127.0.0.1:8723/mcp` | MCP-сервер Foreman; модели не выставляется |
| `FICSITAI_API_VERSION` | `0.4.0` | версия публичного API мода ([docs/interfaces/public-api-v0.md](../../docs/interfaces/public-api-v0.md)); значение по умолчанию идёт за контрактом, и это дублирование — проверку на совпадение в CI попросил у Gf2 (Co2-12) |
| `LLM_UPSTREAM_BASE_URL` | — | настоящий адрес провайдера. Задан — поднимается нормализатор (ADR-034); не задан — Foreman ходит к провайдеру сам. **Строка запроса в адресе допустима** (некоторые шлюзы так передают ключ): путь базы и путь запроса складываются как пути, параметры — как параметры. При совпадении имени побеждает запрос, и побеждает целиком: имя из запроса вытесняет значения базы, а все его повторы доходят до провайдера (`?mode=one&mode=two` не сворачивается в последнее значение, ревью Gs-15) |
| `NORMALIZER_PORT` | `8731` | порт нормализатора, тоже только петля |
| `FOREMAN_ACCOUNT_PATH` | `~/.local/share/ficsitai/foreman/adapter-account.json` | файл локального аккаунта Foreman: создаётся при первом запуске с правами 600, пароль случайный. Путь задаёт лаунчер — каталог данных выбирает он, не адаптер |
| `ADAPTER_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |

## Запуск

Отдельно (нужен Node 22):

```bash
npm install
ADAPTER_TOKEN=$(cat ~/.local/share/ficsitai/foreman/adapter.token) npm run dev
```

Вместе с Foreman — [`../launcher/dev/foreman-local.sh`](../launcher/dev/foreman-local.sh).

Проверки: `npm run typecheck`, `npm run build`, `npm test`.

`test/chat.test.ts` держит API чата: отказ без токена, ход до Foreman и обратно кадрами, многобайтный символ, разорванный между пакетами, ошибка Foreman кадром `error`, пустое сообщение без похода к Foreman, `409` на второй ход, отмена (поток моду закрыт, Foreman дочитан, остаток ответа моду не адресован), ожидание следующего хода до конца дочитывания, повторная отмена, хвост истории и её размер по умолчанию. Поддельный Foreman — настоящий слушатель на петле, отвечающий настоящим SSE.

`test/whitelist.test.ts` держит белый список и **согласие промпта с ним**: ни одного скрытого имени в промпте, видимые на месте, тот же разбор блока, что у Foreman, подстановки целы, уведомление об изменении — вне блока.

`test/stream.test.ts` держит разбор SSE (имя события, несколько строк `data`, комментарии и keep-alive, оборванный поток без пустой строки в конце, `\r\n`) и сборку кадров наружу.

`test/foreman.test.ts` держит вход и сопоставление сохранения: обычный вход одним запросом, регистрация только когда вход не прошёл, отказ без пароля в тексте ошибки, повтор после `401`, обязательный `Origin`, идентификатор playthrough из `saveId`, гонка двух запусков (`409` — не ошибка) и права `600` у файла аккаунта. Поддельный Foreman — настоящий слушатель на петле, а не подменённый `fetch`.

`npm test` держит замечания ревью Gs-11, Gs-14 и Gs-15 (`test/normalizer.test.ts`): признак `tool_calls` отдельно для каждого варианта ответа, соседние поля `extra_content.google`, подпись из обычного JSON-ответа, граница кэша подписей по разговору, маскировка ключа провайдера, версия API, отказ от перехода по `Location` (два локальных сервера: второй не должен увидеть ключ), сборка адреса, когда в базе есть строка запроса, и повторяющийся параметр запроса, который доходит до провайдера обоими значениями. Каждая проверка падает на прежней логике — иначе она ничего не стоит.

Сквозные сценарии (исправный поток, поломка провайдера, отказ `400` без подписи) живут у Gf2 в [`tests/fake-llm/`](../../tests/fake-llm/README.md): исправный и сломанный поток должны лежать рядом (Co-23). Прогон собранного адаптера против этого сервера — часть проверки P-3, а не эмуляция парсера.
