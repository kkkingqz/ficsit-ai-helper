# `launcher` — запуск сайдкара и сборка архива

Здесь живёт всё, что поднимает сайдкар: пока — воспроизводимый локальный запуск без Docker (P-3), дальше — лаунчер и архив для альфы (S5-lite, [#13](https://github.com/kkkingqz/ficsit-ai-helper/issues/13)).

## Зафиксированный коммит Foreman

[`foreman.pin.json`](foreman.pin.json) — репозиторий, коммит, дата, лицензия и версии рантайма. Коммит меняется **только отдельной задачей** (R-17): прогнать тесты адаптера с fake-LLM, сверить окружение и API чата, записать новый коммит в файл.

Клон на этой машине — `~/Projects/foreman-src`, вне репозитория: Foreman не вендорится и не форкается (ADR-012).

```bash
git clone https://github.com/StuartMeeks/ficsit-foreman ~/Projects/foreman-src
cd ~/Projects/foreman-src && git checkout 08bebe16f3f459170479f5ded3b040087cf43593
npm ci && npm run build
```

## Локальный запуск

```bash
sidecar/launcher/dev/foreman-local.sh migrate   # схема Prisma в SQLite
sidecar/launcher/dev/foreman-local.sh start     # sf-mcp, ff-server, адаптер
sidecar/launcher/dev/foreman-local.sh status    # слушатели; ненулевой код, если что-то лежит
sidecar/launcher/dev/foreman-local.sh stop
```

Node 22 берётся системный; если его нет, а есть `nix`, скрипт поднимает разовый `nix shell nixpkgs#nodejs_22` — профиль пользователя не меняется. Данные (база, саveы, токен, логи, pid) лежат в `~/.local/share/ficsitai/foreman`, вне репозитория.

| Процесс | Адрес | Чем занят |
|---|---|---|
| `sf-mcp` | `127.0.0.1:8723` | игровые данные и сохранения; модели не выставляется |
| `ff-server` | `127.0.0.1:8724` | чат, аккаунты, playthrough, work orders |
| адаптер | `127.0.0.1:8730` | единственный `MCP_URL` Foreman |
| нормализатор | `127.0.0.1:8731` | `LLM_BASE_URL` Foreman; **тот же процесс, что адаптер** (ADR-034) |

Адаптер поднимается собранным (`npm run build` + `npm run start`). `ADAPTER_MODE=dev` включает `tsx watch` — осознанно и только на машине разработки: наблюдатель переподнимает процесс на каждую правку, и при нескольких поколениях они дерутся за порт, а выжившее отвечает со старой конфигурацией.

**`start` и `status` судят по слушателю, а не по записанному pid.** `start` ждёт порт до 40 секунд и при неудаче печатает хвост лога и возвращает ошибку; `status` отдельно называет случай «pid жив, а порт никто не слушает» и выходит с ненулевым кодом.

Иначе получается ложное зелёное, и оно уже случилось: 10.11.2026 `node` адаптера умер на старом вызове `tsx`, а `status` полтора часа показывал «работает» — записанный pid принадлежал голове цепочки обёрток (`nix`, `npm`), которая переживает собственного внука. Проверка в чек-листе Gf2 на такой `status` опирается, поэтому признак работы — порт.

## Провайдер LLM: Gemini

Решение King 10.11.2026 — **Gemini**. Своего провайдера для Gemini у Foreman нет, и он не нужен: подключаемся через **OpenAI-совместимый эндпоинт Google**, под который там и сделан `LLM_BASE_URL`.

| Переменная | Значение |
|---|---|
| `LLM_PROVIDER` | `openai` |
| `LLM_BASE_URL` | `https://generativelanguage.googleapis.com/v1beta/openai` |
| `LLM_MODEL` | `gemini-3.5-flash-lite` — единственная из проверенных, что отвечает текстом (см. ниже) |
| `LLM_SUMMARY_MODEL` | `gemini-3.5-flash-lite` — дешёвая модель для сжатия истории |
| `LLM_API_KEY` | ключ из Google AI Studio; в репозитории не лежит |

Скрипт выставляет это сам при `FICSITAI_LLM=gemini` (значение по умолчанию); `anthropic` и `openai` тоже принимаются.

```bash
sidecar/launcher/dev/foreman-local.sh set-key   # ключ вводится вручную, не через аргумент
sidecar/launcher/dev/foreman-local.sh models    # имена моделей из API, чтобы не угадывать
```

**Имена моделей нельзя брать из головы.** Список из `models` и реальные ответы OpenAI-совместимого эндпоинта расходятся, проверено 10.11.2026 на нашем ключе:

| Модель | Что отдаёт `/chat/completions` |
|---|---|
| `gemini-3.5-flash-lite`, `gemini-3.6-flash` | отвечают; инструменты вызывают, но см. «потоковый `finish_reason`» ниже |
| `gemini-3.8-flash`, `gemini-3.7-flash`, `gemini-3.5-flash` | `503 UNAVAILABLE` — «high demand», состояние временное |
| `gemini-3.1-pro-preview` | `429` — квота: модели класса pro на бесплатном уровне недоступны |
| `gemini-2.5-pro`, `gemini-2.5-flash` | `404 NOT_FOUND`, хотя в списке `models` они есть |

### Нормализатор ответов провайдера (ADR-034)

`LLM_BASE_URL` Foreman указывает не на провайдера, а на **нормализатор** — слушатель на петле в процессе адаптера. Он проксирует запросы к провайдеру и приводит ответы к тому, что ожидает OpenAI-совместимый клиент. Основание не в поломке одного провайдера, а в AC-12 и V-08: альфа принимает любой OpenAI-совместимый адрес и локальные модели, у которых обращение с `finish_reason` вольное.

Что он правит, проверено на живом ключе 10.11.2026:

| Поломка | Что делает нормализатор |
|---|---|
| `finish_reason: "stop"` при наличии `tool_calls` в потоке | ставит `"tool_calls"` — иначе `ff-server` считает ход законченным и молча выбрасывает вызовы |
| `400 Function call is missing a thought_signature` на втором ходе | запоминает `thought_signature` из `extra_content` по идентификатору вызова и возвращает её в следующий запрос |
| ошибка, завёрнутая в массив из одного элемента | разворачивает |

Что он **не** делает: не добавляет и не меняет системные промпты, не переписывает определения инструментов, не фильтрует содержимое, не логирует тела запросов и ответов. В логе — только метод, путь, код и число правок.

Выключается `FICSITAI_NORMALIZER=off`: тогда Foreman ходит к провайдеру напрямую и вызовы инструментов у Gemini теряются.

### Потоковый `finish_reason` ломает вызовы инструментов

**Главная находка P-3, и она не про выбор модели.** OpenAI-совместимый эндпоинт Google в потоковом режиме отдаёт `finish_reason: "stop"` даже тогда, когда в том же ответе пришли `tool_calls`. В непотоковом режиме тот же запрос отдаёт корректный `finish_reason: "tool_calls"`. Проверено 10.11.2026 на `gemini-3.5-flash-lite` и `gemini-3.6-flash`:

| Режим | `finish_reason` | `tool_calls` |
|---|---|---|
| `stream: true` | `stop` | есть |
| `stream: false` | `tool_calls` | есть |

`ff-server` всегда стримит и решает по `finish_reason`:

```ts
return { text, toolCalls, stopReason: finishReason === 'tool_calls' ? 'tool_use' : 'stop' };
```

Поэтому вызовы инструментов собираются и **молча отбрасываются**: модель попросила `total_raw_inputs`, Foreman закончил ход, в SSE — только `event: done`, ни текста, ни ошибки. Снаружи это выглядит как «чат не отвечает», а на самом деле сломан ровно путь модель → инструмент → ответ, то есть критерий V-04.

**Решено:** ADR-034 — нормализация в сайдкаре (см. выше) плюс upstream-PR в Foreman параллельно. Патчить Foreman у себя нельзя (ADR-012).

Проверено после включения нормализатора: модель вызывает `ingredient_tree` через адаптер, получает результат и отвечает цифрами — путь модель → инструмент → ответ работает целиком.

Поэтому модель меняется одной переменной, а перед сменой прогоняется `models` и пробный запрос. Ключ лежит в `~/.local/share/ficsitai/foreman/llm.key` с правами 600, вводится без эха и не попадает ни в историю команд, ни в логи. **`LLM_SUMMARY_MODEL` задавать обязательно:** при `LLM_PROVIDER=openai` Foreman по умолчанию берёт `gpt-4.1-mini`, и на ключе Google сжатие истории падало бы отдельно от чата.

**Подписка Google AI Pro сама ключа к API не даёт** — она про приложение Gemini. Ключ к Gemini API берётся в [AI Studio](https://aistudio.google.com/apikey) на том же аккаунте: есть бесплатный уровень с лимитами и платный через биллинг проекта. Для альфы это важно: тестеры вводят **свой** ключ при первом запуске, и подписка им не поможет — это пункт в инструкции, а не мелочь.

## Что легко сделать не так

- **`MCP_TRANSPORT=http` обязателен.** По умолчанию `sf-mcp` работает по stdio и порт не слушает вовсе; в плане этот пункт не назван, а без него `MCP_HTTP_HOST` ни на что не влияет.
- **Оба процесса по умолчанию слушают `0.0.0.0`:** `MCP_HTTP_HOST=127.0.0.1` у `sf-mcp` и `HOST=127.0.0.1` у `ff-server`. Это прямо критерий V-08 (брандмауэр Windows не спрашивает разрешений).
- **У `sf-mcp` в режиме HTTP нет аутентификации** — это сказано в его собственной документации. Единственная защита — петля, поэтому адрес привязки важнее, чем кажется.
- **`ff-server` пишет `MCP_URL` в лог целиком, вместе с нашим токеном.** Это его код, мы его не патчим; наши логи токен вычищают. Токен одноразовый на установку и лежит в `adapter.token` с правами 600.
- **`BETTER_AUTH_SECRET`** не задан — `ff-server` генерирует его сам и кладёт рядом с базой, сессии выживают перезапуск. Для альфы этого достаточно.
- **`SAVE_DATA_DIR` один и тот же** у `ff-server` и `sf-mcp`: бэкенд кладёт туда загруженные `.sav`, а `sf-mcp` только оттуда их и читает. Пригодится источнику Save в S6.
- **Ключ LLM-провайдера в репозиторий не попадает.** Без него поднимается всё, кроме ответа в чате: `ff-server` предупреждает, что клиент должен прислать свой ключ в заголовке `x-anthropic-api-key` (имя заголовка не меняется и для Gemini — это просто имя).

## Чего здесь пока нет

Архив (портативный Node 22, `ff-server`, `sf-mcp`, адаптер, движок Prisma), две раскладки — Linux для разработки и Windows для альфы, прогон под wine, первый запуск с вопросом про провайдера и ключ. Это S5-lite, недели 4–5. Полный S5 с установщиком и Node SEA — этап 3.
