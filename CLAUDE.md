# FICSIT AI — инструкции для сессий, работающих над проектом

Читается автоматически в начале работы. Здесь только то, что нельзя вывести из кода и документов: кто ты в проекте, где источник истины и какие правила действуют поверх задач.

## 1. Роль назначает King в чате

**Свою роль бери из слов King в текущем разговоре, а не из памяти.** Каталог памяти (`~/.claude/projects/.../memory/`) общий для всех сессий проекта: 09.11.2026 файл с ролью одной сессии был дважды перезаписан другими, и каждая по очереди пометила его как «роль этой сессии». Если файл памяти называет тебя иначе, чем King в чате, — верно то, что сказал King, а о расхождении скажи ему и не переключайся молча.

## 2. Источник истины

1. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — архитектура, ADR, реестр рисков, критерии приёмки. **При любом расхождении прав этот документ.**
2. [docs/PLAN-v0.1.md](docs/PLAN-v0.1.md) — план этапа 1: недели, исполнители, оценки.
3. [docs/MODULES.md](docs/MODULES.md) — реестр модулей: что берём готовым, что пишем сами.
4. Задачи [milestone v0.1](https://github.com/kkkingqz/ficsit-ai-helper/milestone/1) — чек-листы и критерий «готово».
5. [docs/interfaces/](docs/interfaces) — интерфейсы кода: эскизы и замороженные контракты.
6. [docs/contracts/](docs/contracts) — JSON Schema контрактов и примеры; проверяются в CI.

**Статус проекта: кода пока нет.** Репозиторий содержит архитектуру и план на согласование, а не описание реализованного продукта. Структуру каталогов создаёт задача P-2.

## 3. Решения

- Решения по итогам спайков **пишет Co в `ARCHITECTURE.md`, утверждает King** на воротах. Решение, оставшееся в задаче, в комментарии или в переписке, — не решение.
- Новое архитектурное решение оформляется ADR в §16 с номером, статусом и ссылками на затронутые разделы. Последний номер — ADR-033.
- Нашёл расхождение между документами — правь документ и скажи об этом, а не обходи молча.

## 4. Чьи файлы ты правишь

**Каждый коммитит только файлы своей зоны.** Зоны — [docs/team/OWNERSHIP.md](docs/team/OWNERSHIP.md). Нужен чужой файл — не правь, а задай вопрос владельцу в [docs/team/questions/](docs/team/questions/README.md): вопрос пишется в **свой** файл, ответ — в файл отвечающего, поэтому чужое не трогает никто.

Клон `~/Projects/ficsitai` **общий**: несколько сессий правят одно рабочее дерево и одну ветку. Поэтому запрещено `git add -A`, `git add .`, `git commit -a` (заберут чужие недоделанные файлы), `git stash`, `git reset --hard`, `git checkout -- .`, `git clean` (уничтожат чужую работу), а также переключение ветки и `rebase` в общем клоне. Вместо этого: `git status`, затем `git add` с конкретными путями, затем `git diff --cached --name-only` глазами.

**Коммит подписывается ролью:** строка `Роль: <Роль>` в сообщении. Все коммиты идут от одной идентичности, и без этой строки непонятно, кто работал.

## 5. Правила работы

- **Каждый PR в мод проходит ревью Co.** Код Co ревьюит Gs. Контрактную поверхность адаптера (инструменты из реестра, белый список, `apiVersion`, формат канала) ревьюит Co.
- **Лаунчер, сборка архива и вёрстка экранов ревью не проходят** — второго веб-программиста нет. Вместо ревью чек-лист Gf2 и тесты с fake-LLM. Это сознательное ограничение, а не покрытие.
- **Работа готова по чек-листу Gf2 (P-7), а не по ощущению.** Перед началом спайка чек-лист уже должен быть.
- **Задержка больше дня по задаче критического пути — сразу Co и King.**
- **Заимствованный код — в `third_party/<project>/`** с исходным файлом лицензии и перечнем изменений. Не копипастой в свои файлы.
- **Код с художественных ветвей** (`art/*`) до слияния в `main` не считается кодом проекта, а при слиянии проходит обычное ревью.
- **`main` защищается на зелёный CI** задачей P-2. До этого King разрешил коммитить документы прямо в `main`; после — только ветки и PR.

## 6. Инварианты, роняющие сборку (ADR-029, AC-21)

1. Типы `AFG*`/`UFG*` допустимы **только** в `GameFacade/`.
2. `FicsitAIUI` собирается без заголовков игры и SML.
3. В обработчиках сообщений сайдкара нет вызовов мутирующего игрового API.
4. Операция, выставленная модели без ручной точки входа, роняет сборку (тест паритета).

Предложено пятым: имя класса терминала не встречается в `FicsitAIUI` — модуль не кастуется к хосту.

## 7. Решения, которые легко нарушить не зная

- **Модель не изменяет игровой мир.** Это постоянный инвариант, а не объём версии (ADR-009): строительство, демонтаж, рецепты, такт и транспорт остаются ручными во всех версиях v1.x.
- **Паритет:** инструмент модели не появляется раньше своего ручного пути в UI (ADR-018).
- **Только одиночная игра.** Мультиплеер и Dedicated Server — вне v1.x; в мультиплеерной сессии мод инертен.
- **Foreman не форкается и не патчится** (ADR-012): подключается через адаптер, расхождения гасятся там.
- **Перед реализацией модуля проверь, нет ли готового средства SML** (ADR-027): конфигурация, персистентность, реестр контента, клавиши — у платформы.
- **Единицы:** `items/min`, `m3/min`, MW. Перевод внутренних единиц жидкостей — один раз, на границе `CatalogProvider` (§5.6).
- **Язык:** документы и коммиты русские; строки интерфейса v0.1 английские и идут через UE Localization.
- **Элементы концепта, меняющие мир, не реализуются** (§6.8): ползунки такта только отображают, «изменить рецепт» и «настроить маршрут» не рисуются.

## 8. Среда (машина King)

- **Целевая платформа игроков — Windows-клиент**, нативного Linux-клиента у игры нет. **Платформа разработки — Linux, игра под Proton** (ADR-033): мод под Win64 собирается MSVC под wine по официальному Linux Setup SML, движок берётся готовым архивом редактора.
- **Windows-машины в команде нет.** Всё, что требует настоящей Windows (AC-12, V-08), выполняет пилотный тестер, а не команда.
- Сессии работают в Flatpak-песочнице: `git` и `gh` доступны только через `flatpak-spawn --host`. Файлы правятся обычными средствами.
- **CI срабатывает только на изменения в `docs/contracts/**`.** Зелёный CI не подтверждает правки документов — это не признак того, что проверка не прошла.
- Коммиты подписываются строкой `Co-Authored-By` своей модели; сообщения — на русском, с префиксом вида `docs:`.
