# `screens/api` — фасад публичного API мода

Один интерфейс для экрана в двух средах: в игре фасад идёт **мостом** к `FicsitAIApi`, в браузере — **HTTP** к dev-серверу. Экран пишется один раз и отлаживается без игры (ARCHITECTURE §13, ADR-026, ADR-032; S6, [#12](https://github.com/kkkingqz/ficsit-ai-helper/issues/12)).

```js
import { createApi } from "@ficsitai/screens-api";

const api = createApi();              // транспорт выбирается по среде
const status = await api.getStatus();
const value = await api.queryMetric({ metricId: "power.production" });
api.on("metrics.snapshot", () => redraw());
```

## Что фасад делает и чего не делает

Он тонкий нарочно. Всё, что он добавляет к контракту, — выбор транспорта, единая форма ошибки и типы.

- **Не придумывает данные.** Ни кэша, ни значений по умолчанию, ни повторов запроса. Где экран показывает прочерк — прочерк и пришёл: `state: "notApplicable"`, `value: null` (правило Gs-13 контракта).
- **Не перекладывает формы.** Ответ типизирован, но это тот же объект, что пришёл. Вторая форма стала бы второй правдой при каждой правке контракта.
- **Не хранит состояние мода.** Статус спрашивают, события приходят; что из этого показать — дело экрана.
- **Не знает про чат.** Запросы чата появятся в API вместе с мостом (минорная 0.5.0, Co-82); тогда к фасаду добавятся `chatSend`, `chatCancel`, `chatHistory`.

Поверхность фасада — **подмножество API 0.5.0**: статус, каталог, области, значение и ряд. Запросы чата (`chatSend`, `chatCancel`, `chatHistory`) и события `chat.*` придут отдельным PR вместе с мостом (Co-82); типы состояния ассистента (`assistantState`, `assistantModel`) уже здесь, потому что их отдаёт `getStatus` и событие `api.status`.

Формы, коды ошибок и семантика — из [public-api-v0.md](../../../docs/interfaces/public-api-v0.md). При расхождении прав документ, а не этот пакет: контракт задаёт Co, утверждает Gs.

## Транспорты

| Среда | Как работает |
|---|---|
| Игра | `blu_event("ficsitai.bridge", { id, op, args })`, ответ — `window.__ficsitaiBridge.receive({ re, body \| error })`, события — `{ event, data }` ([конверт моста](../../../docs/interfaces/web-runtime-plugin.md#конверт--для-фасада-co2)) |
| Браузер | `POST /api/v0` с тем же конвертом, события — `text/event-stream` на `/api/v0/events` |

Конверт нарочно один и тот же: экран, отлаженный в браузере, не встречает в игре другой формы, а разница между средами остаётся в одном файле на транспорт.

**Диспетчер ответов на странице один.** Второй `createApi()` раньше подменял `window.__ficsitaiBridge.receive`, и запросы первого висели вечно. Теперь ожидающие запросы и подписки живут **на странице** (`window.__ficsitaiBridgeState`), а не в модуле: страница может загрузить модуль дважды — двумя импортами с разными URL, экраном и виджетом из разных сборок, — и копии подключаются к одному диспетчеру вместо того, чтобы подменять друг друга (повторное ревью Gs на #53). `close()` завершает отказом свои ожидающие запросы и не трогает чужие. Если приёмник подменит сторонний сценарий, фасад ставит свой заново при следующем запросе, не теряя ожидающих.

Три правила моста соблюдает фасад, а не мод:

1. **`id` уникален на странице** — случайный префикс плюс счётчик, поэтому ответ прежней страницы после перезагрузки не попадёт в новую.
2. **Предел 64 КиБ проверяется до отправки.** Конверт больше мод отбрасывает молча, и запрос без этой проверки висел бы вечно. Отказ — `TOO_LARGE`, локально.
3. **Ответ с незнакомым `re` пропускается** — так выглядят ответы после перезагрузки или после срока; их видно в `window.__ficsitaiBridge.stray`.

Своего срока у моста нет, поэтому срок держит фасад: по замерам S8 мост отвечает за кадр (медиана 13 мс), так что молчание дольше секунд — это потеря, а не медленная работа. Без срока экран замирал бы молча.

## Dev-сервер

**Все команды — из корня репозитория**, одной последовательностью. Прежде они были написаны частью от корня, частью из каталога пакета: из корня не находился `dist/dev/cli.js`, а из пакета — ни сохранение, ни страницы (ревью Gs на #66). Относительные пути (`--root`, `--mount`, `--save-file`, `--source`) разрешаются от каталога запуска, поэтому каталог должен быть один.

```bash
# сборка: сам фасад и, если нужен источник Save, библиотека Cf3
npm --prefix web/screens/api install
npm --prefix web/screens/api run build
npm --prefix sidecar/save-source install && npm --prefix sidecar/save-source run build

# источник demo — ничего больше не нужно
node web/screens/api/dist/dev/cli.js --root web --port 5173

# свой источник: модуль с createSource()
node web/screens/api/dist/dev/cli.js --root web --source ./my-source.js

# данные из сохранения; --source saveEstimated — оценочные скорости (§8.5)
node web/screens/api/dist/dev/cli.js --root web \
  --mount /third_party=third_party \
  --source save --save-file fixtures/saves/save_a_starter.sav
```

Экраны после этого открываются по адресам `/screens/chat/index.html` и `/screens/statistics/index.html`; у «Статистики» ещё должна быть собрана своя сборка (`npm --prefix web/screens/statistics install && npm --prefix web/screens/statistics run build`).

- `POST /api/v0` — запросы API v0 тем же конвертом, что на мосту;
- `GET /api/v0/events` — события источника плюс `reload` при правке файла;
- `GET /api/v0/reload.js` — клиент горячей перезагрузки, подключается строкой `<script src="/api/v0/reload.js"></script>`;
- остальное — статика из `--root`, без кэша (иначе горячая перезагрузка бессмысленна).

Сервер отвечает кодами контракта, а не страницами: конверт не объект, нет `id` или `args` не объект — `INVALID_ARGUMENT`, незнакомый `op` — `UNKNOWN_OP`, ошибка источника — его собственный код. Некорректный адрес запроса (`GET //[`) — тоже `INVALID_ARGUMENT`, а не падение процесса. Путь за пределы `--root` закрыт и по строке, и по фактическому пути после разрешения символических ссылок: ссылка из корня наружу отдавала чужой файл (ревью Gs на #53).

**Источник — это объект с пятью методами API v0** (`src/dev/source.ts`). Сервер их не содержит, а подключает: модуль из `--source` экспортирует `createSource()`. Путь к файлу разрешается от каталога запуска (а не от `dist/dev/`) и через `pathToFileURL`, поэтому `--source ./my-source.js` работает и на Windows. Так наборы Fixture и проигрыватель Recording (Gf2) приедут без правки сервера. Источник Save (Cf3) подключён своим флагом — ниже; наборов Fixture в репозитории пока нет (`fixtures/` содержит только спецификацию, неделя 4).

### Источник Save

`--source save` (или `--saveEstimated`) подключает библиотеку Cf3 `sidecar/save-source/` и отдаёт экранам числа из файла сохранения — без игры, без сайдкара и без мода.

| Флаг | Переменная | Что это |
| --- | --- | --- |
| `--save-dir` | `SAVE_DATA_DIR` | каталог сохранений |
| `--save-id` | `FICSITAI_SAVE_ID` | имя сохранения в каталоге |
| `--save-file` | — | путь к конкретному `.sav` вместо пары выше |
| `--save-package` | `FICSITAI_SAVE_SOURCE` | где искать сборку пакета (по умолчанию `sidecar/save-source/dist/index.js` от каталога запуска) |

Пакет не в зависимостях фасада нарочно: он Node-овый, тянет сборки Foreman из `FOREMAN_SRC` и нужен только dev-серверу, а страница грузит `dist/index.js`. Подключается динамическим импортом и только когда его позвали, поэтому `npm install` здесь от него не зависит. Обёртка (`src/dev/save-source.ts`) делает три вещи: переводит `FicsitAIApiError` в форму ошибки сервера, договаривает статус до 0.5.0 (`assistantState: "unavailable"` — чата у сохранения нет) и больше ничего: формы ответов чужие, кэш снимка по `mtime` у пакета свой.

Чего у этого источника нет по природе: ряда (`SERIES_NOT_AVAILABLE`, в каталоге это видно заранее по `hasSeries: false`), событий (снимок один) и чата. Про чат статус говорит словами: `assistantState: "unavailable"` и причина в `reason` — контракт отводит это поле именно под причину, и пустым его оставлять нельзя (ревью Gs на #66). Причину источника, если он её назвал, не затираем: его важнее нашей. Версию API пакету не объявляем: он сверяет её строгим равенством и на 0.5.0 отказал бы всему, хотя мажор тот же, — расхождение версий видно в статусе, там ему и место (§5.5).

### Врезки каталогов

Экран может ссылаться за пределы корня страниц: «Статистика» просит uPlot из `third_party/` рядом с `web/`, а `ui-kit/` — из `web/`. С одним корнем один из двух адресов неизбежно отдавал 404 (я сам потерял на этом прогон ревью #59 и принял чужой экран за неработающий). `--mount <префикс>=<каталог>` можно задать несколько раз (команда — выше, в блоке запуска); выход за каталог врезки закрыт так же, как выход за корень, — и по строке, и по ссылке. Врезка выбирается по **адресному** пути, а не по пути файловой системы: `path.normalize` на Windows меняет прямые слеши на обратные, и `/third_party/…` перестал бы совпадать с префиксом (ревью Gs на #66). Пустая правая часть флага — отказ до старта: `resolve("")` даёт каталог запуска, и статика молча расширялась до него. За изменениями во врезках сервер не следит: там вендор, а горячая перезагрузка нужна для своего кода.

Встроенный источник `demo` — **не замена наборам Fixture**. В нём ровно столько, сколько нужно для проверки самого фасада: значение, неприменимое значение, ряд с пропуском, области с пагинацией и все коды ошибок контракта. Подменять им наборы нельзя: разойдутся две правды о том, что значит «пустая фабрика».

## Пример

`example/index.html` — страница на фасаде: статус, каталог, значения и перерисовка по событию снимка. Она же проверка связки в браузере:

```bash
node dist/dev/cli.js --root . --port 5173
# http://127.0.0.1:5173/example/index.html
```

## Проверки

`npm run typecheck`, `npm run build`, `npm test` — 29 проверок, включая шесть замечаний ревью Gs на #53.

`test/bridge.test.ts` держит мост: конверт и канал, уникальность `id`, отказ `TOO_LARGE` до отправки, пропуск чужого `re`, ошибка мода кодом контракта, срок вместо вечного ожидания, события, выбор транспорта и расхождение мажорной версии в статусе (по §5.5 оно не исключение: ручные функции продолжают работать).

`test/dev-server.test.ts` держит браузерную сторону: формы статуса, каталога, значения и ряда, неприменимое значение прочерком, пропуск в ряду по `timestamps`, пагинация областей и невзаимозаменяемость курсоров, коды `UNKNOWN_METRIC`, `SCOPE_REQUIRED`, `SCOPE_NOT_FOUND`, `SERIES_NOT_AVAILABLE`, `INVALID_ARGUMENT`, `UNKNOWN_OP`, раздача страниц и отказ выйти за корень, горячая перезагрузка по правке файла и событие снимка до подписчика фасада.

Связка проверена в браузере целиком: страница открыта с dev-сервера, значения пришли, правка файла перезагрузила вкладку, событие снимка дошло до страницы.
