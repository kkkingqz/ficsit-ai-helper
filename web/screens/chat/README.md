# @ficsitai/screen-chat

Типы экрана «Чат с ИИ» (**V-6**, [#23](https://github.com/kkkingqz/ficsit-ai-helper/issues/23)): строки от хоста и свойства представления. Это первая часть экрана — состояние, вызовы фасада и точка входа `index.html` приходят вместе с запросами чата в фасаде (`chatSend`, `chatCancel`, `chatHistory`), отдельным PR.

Зоны разведены по [ADR-032](../../../docs/ARCHITECTURE.md) и ответу [Gs2-25](../../../docs/team/questions/Gs2.md): представление `mountChat` — у Gs2 в `web/ui-kit/screens/chat.js`, экран — здесь.

## Что отдаётся представлению

```ts
import { DEFAULT_CHAT_STRINGS, type ChatViewModel, type MountChat } from "@ficsitai/screen-chat";

const view = mountChat(root, {
  presenter,                      // форматтер D-2, его даёт хост
  copy: DEFAULT_CHAT_STRINGS.view, // ChatViewCopy — замороженный набор ключей
  actions,                         // ChatActions — обработчики, события к экрану
});

view.update(model); // ChatViewModel
```

Правило разделения простое: представление — чистая функция от свойств. Оно не ходит в фасад, не хранит состояние между вызовами `update` и не придумывает слов. Любой его обработчик — событие к экрану, любое изменение на экране — новый `update`.

## Две группы строк

| Группа | Куда идёт | Зачем |
| --- | --- | --- |
| `ChatViewCopy` (`DEFAULT_CHAT_STRINGS.view`) | в `mountChat` как `copy` | всё, что представление показывает само: заголовки, подсказки, состояния истории, шаблоны, метки панелей |
| `ChatHostStrings` (`DEFAULT_CHAT_STRINGS.host`) | остаётся у экрана | то, чем экран заполняет поля модели: `messages[].time`, `messages[].status`, `error.text`, `rateLimit` |

Деление не формальность: `error.text` и пометки сообщений приходят в представление уже локализованными, поэтому слова для них должны жить там, где они создаются, — на экране. Набор ключей `ChatViewCopy` заморожен, недостающий ключ ловится сборкой, а не прочерком на экране. Нужен новый — скажите, добавлю: придумывать строки в представлении не надо.

Подмена — `createChatStrings({ view, host })`. Вложенные объекты заменяются целиком, чтобы половина подменённого `historyStates` не оставила экран с чужой половиной.

## Семантика, которая влияет на кнопки

- **Stop — это «перестать показывать», а не «остановить ход».** Foreman дочитывает ход, и ответ окажется в истории при следующем чтении. Полученный фрагмент остаётся на экране с пометкой `messageStatus.stopped`.
- **Повтора в API нет.** `actions.retry()` — это новый `chat.send` с тем же текстом и новым `turnId`; прежний ход остаётся в истории. Повтор доступен только при связи с сайдкаром.
- **`sending` против двойной отправки.** Экран ставит флаг в обработчике `send` и снимает при идентификаторе хода или ошибке, поэтому повторный Enter до появления хода ничего не отправляет.
- **Пустая история и недоступная — разные состояния.** `empty` значит «разговора ещё не было», `unavailable` — «прежние сообщения не загрузились»; путать их нельзя.

## Демонстрационные данные

`chatDemoModel(state)` даёт детерминированную модель для каждого из состояний `ready`, `empty`, `loading`, `streaming`, `sending`, `error`, `offline`. Это данные для вёрстки и дымовых проверок, не телеметрия: в экране их нет, он строит модель из фасада.
