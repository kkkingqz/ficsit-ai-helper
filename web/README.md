# `web/` — веб-экраны

Фронтенд-проект экранных модулей и рендерера `ScreenDefinition`: один и тот же код работает в игре внутри UMG-каркаса через мост BLUI и в браузере на dev-сервере (ARCHITECTURE §6.3.1, ADR-032).

| Каталог | Кто | Что внутри |
|---|---|---|
| `screens/` | Co2 | логика страниц и фасад API |
| `ui-kit/` | Gs2 | дизайн-система (D-2) и компоненты |
| `spikes/` | тот, кто ведёт спайк | `spikes/s8/` — Gs2 и Co |

Источник истины по зонам и по этому разделению — [docs/team/OWNERSHIP.md](../docs/team/OWNERSHIP.md), а не этот файл.

Фасад — один интерфейс поверх двух транспортов: привязка JavaScript к `FicsitAIApi` в игре и HTTP к адаптеру в браузере. Строится на **замороженном контракте API v0** от Co, а не на эскизе (S6, [#12](https://github.com/kkkingqz/ficsit-ai-helper/issues/12)).

**Продуктовый код экранов появляется здесь только если ADR-032 принят** на воротах W. При варианте UMG вместо него — `screenlab/` и UMG-экраны.

**Исключение — `spikes/s8/`** (решение 10.11.2026 по Gs2-1): каталог спайка разрешён до ворот W, потому что он и даёт данные для решения ADR-032. Если вариант отклонят, `spikes/s8/` удаляется целиком, а не переезжает в продуктовый код.

Вёрстка и дизайн-система — Gs2, логика и фасад — Co2. Ревью вёрстки нет: вместо него чек-лист Gf2 и автотесты экранов на Fixture в браузере.
