**Первые пять минут.** Прочитай по порядку: этот файл → [docs/team/KICKOFF.md](docs/team/KICKOFF.md) (с чего начинаешь, точки передачи, чего делать не надо) → свой файл роли в [docs/team/](docs/team/README.md) → свои задачи в [milestone v0.1](https://github.com/kkkingqz/ficsit-ai-helper/milestone/1). ## 3. Твоя рабочая копия

У каждой роли **своя** рабочая копия (решение King 09.11.2026), потому что в общем рабочем дереве сессии затирали друг друга:

| Путь | Что это |
|---|---|
| `~/Projects/ficsitai-<роль>` | Твоя копия, ветка `work/<роль>`. Работай только здесь |
| `~/Projects/ficsitai` | **Узел.** Ветка `main`, файлы руками не правятся — только посмотреть собранное состояние |

Копии сделаны через `git worktree`, объекты общие — каждая около 21 МБ при репозитории в 535 МБ. Своей копии нет — создай один раз:

```bash
/usr/bin/git -C ~/Projects/ficsitai worktree add -b work/<роль> ~/Projects/ficsitai-<роль> origin/main
```

**Порядок работы.** Свежий `main` — `/usr/bin/git fetch origin && /usr/bin/git rebase origin/main` в своей копии. **Документы** уходят прямо в `main`, пока это fast-forward: `/usr/bin/git push origin HEAD:main`; отказ значит, что кто-то успел раньше, тогда fetch, rebase и снова. **Код** идёт через задачную ветку и PR по [CONTRIBUTING.md](CONTRIBUTING.md): `git switch -c mod/s1-terminal origin/main` в своей же копии.

**Коммит подписывается ролью:** строка `Роль: <Роль>` в сообщении. Все коммиты идут от одной git-идентичности, и без этой строки по истории не видно, кто работал.

**Запреты:**

| Нельзя | Почему |
|---|---|
| Править файлы в узле `~/Projects/ficsitai` | это собранное состояние, а не чьё-то рабочее |
| `git add -A`, `git add .`, `git commit -a` без проверки | заберёт чужие пути; так уже уехала чужая работа — см. `OWNERSHIP.md` |
| `git stash` без уникальной метки | стек стэша **общий** у всех копий |
| `git worktree remove` чужой копии, `git branch -D` чужой ветки | удалит чужую работу |
| `git push --force` в `main` | снесёт чужую историю |

Перед коммитом: `git status`, затем `git add` с конкретными путями, затем `git diff --cached --name-only` глазами.

## 6. Ревью и готовность

- **Каждый PR в мод проходит ревью Co.** Для задач Gf это часть плана, а не формальность. **Код Co ревьюит Gs.**
- **Контрактную поверхность адаптера** (инструменты из реестра, белый список, `apiVersion`, формат канала) ревьюит Co.
- **Лаунчер, сборка архива и вёрстка экранов ревью не проходят:** второго веб-программиста в команде нет. Вместо ревью — чек-лист Gf2 и тесты с fake-LLM. Это сознательное ограничение, а не покрытие.
- PR не должен ждать ревью больше дня.
- **Работа готова по чек-листу Gf2 из тест-плана P-7, а не по ощущению.** Чек-лист существует до начала работы.
- **Задержка больше дня по задаче критического пути — сразу Co и King.**
- **Технической защиты `main` нет:** GitHub отдаёт `403 Upgrade to GitHub Pro` на branch protection для приватного репозитория на бесплатном плане. Правило держится соглашением: код — через PR, напрямую в `main` только документы.

## 7. Решения и ADR

- Решения по итогам спайков **пишет Co в `ARCHITECTURE.md`, утверждает King** на воротах. Решение, оставшееся в задаче, в комментарии или в переписке, — не решение.
- Новое архитектурное решение оформляется ADR в §16: номер, статус, ссылки на затронутые разделы. Последний номер — **ADR-033**.
- Ворота этапа 1: **W** — конец недели 3 (веб-экраны или UMG), **G1** — конец недели 5 (переход к сборке v0.1), **G2** — неделя 9 (выпуск альфы).

## 8. Инварианты, роняющие сборку (ADR-029, AC-21)

1. Типы `AFG*`/`UFG*` допустимы **только** в `GameFacade/`.
2. `FicsitAIUI` собирается без заголовков игры и SML.
3. В обработчиках сообщений сайдкара нет вызовов мутирующего игрового API.
4. Операция, выставленная модели без ручной точки входа, роняет сборку (тест паритета).

5. Имя класса терминала не встречается в `mod/FicsitAI/Source/FicsitAIUI/` — модуль не кастуется к хосту (принято Gf2 10.11.2026, вопрос Co-3; до появления класса в S1 правило тривиально зелёное, но сработает при первой же попытке нарушения).

## 9. Решения, которые легко нарушить не зная

- **Модель не изменяет игровой мир.** Постоянный инвариант, а не объём версии (ADR-009): строительство, демонтаж, рецепты, такт и транспорт остаются ручными во всех версиях v1.x.
- **Паритет:** инструмент модели не появляется раньше своего ручного пути в UI (ADR-018).
- **Только одиночная игра.** Мультиплеер и Dedicated Server вне v1.x; в мультиплеерной сессии мод инертен.
- **Foreman не форкается и не патчится** (ADR-012): подключается через адаптер, расхождения гасятся там.
- **Сначала ищи готовое средство платформы** (ADR-027): конфигурация, персистентность, реестр контента, клавиши — у SML и игры, а не свой код.
- **Заимствованный код — в `third_party/<project>/`** с исходной лицензией и перечнем изменений, не копипастой в свои файлы.
- **Код с художественных ветвей** (`art/*`) до слияния в `main` не считается кодом проекта, а при слиянии проходит обычное ревью.
- **Единицы:** `items/min`, `m3/min`, MW. Перевод внутренних единиц жидкостей — один раз, на границе `CatalogProvider` (§5.6).
- **Язык:** документы, комментарии в задачах и сообщения коммитов — русские; строки интерфейса v0.1 — английские и идут через UE Localization.
- **Элементы концепта, меняющие мир, не реализуются** (§6.8): ползунки такта только отображают, «изменить рецепт» и «настроить маршрут» не рисуются.

## 10. Среда

- **Целевая платформа игроков — Windows-клиент**, нативного Linux-клиента у игры нет. **Платформа разработки — Linux, игра под Proton** (ADR-033): мод под Win64 собирается MSVC под wine по официальному Linux Setup SML, движок берётся готовым архивом редактора, а не собирается из исходников.
- **Windows-машины в команде нет.** Всё, что требует настоящей Windows (AC-12, V-08), выполняет пилотный тестер.
- **CI срабатывает только на изменения в `docs/contracts/**`.** Зелёный CI не подтверждает правки документов — это не признак того, что проверка не прошла. Сам мод в CI этапа 1 не собирается.
- Если твой инструмент работает в песочнице (у Claude Code на этой машине это Flatpak), `git` и `gh` могут быть недоступны напрямую: проверь хост, например `flatpak-spawn --host /usr/bin/git --version`, прежде чем объявить их отсутствующими.
- **`git` вызывай полным путём `/usr/bin/git`.** В `~/.local/bin/git` лежит симлинк на `git` из рантайма Codex (появился 10.11.2026), и он перехватывает PATH. Его бинарь сообщает `--exec-path` как `//libexec/git-core`, то есть не находит собственных хелперов, и любой `fetch` или `push` падает с `git: 'remote-https' is not a git command` и `fatal: remote helper 'https' aborted session`. Локальные операции (`add`, `commit`, `log`) у него работают — ломается только сеть, поэтому ошибка выглядит как проблема доступа к репозиторию, хотя дело в PATH. Второй рабочий вариант, если полный путь неудобен: `GIT_EXEC_PATH=/usr/lib/git-core git …` (проверено).
