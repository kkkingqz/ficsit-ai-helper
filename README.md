# FICSIT AI Helper

Мод к Satisfactory и локальный сервис-компаньон, делающие [FICSIT Foreman](https://github.com/StuartMeeks/ficsit-foreman)
инженерным помощником прямо в игре: AI Terminal, экипируемый AI Assistant, производственные
планы, HUD и запросы на создание Blueprint.

**Статус: только архитектура.** Кода пока нет. Репозиторий содержит проект архитектуры
релизной версии, вынесенный на согласование, — не описание реализованного продукта.

## Главное из архитектуры

- **Целевой стек:** Satisfactory 1.2, SML 3.12, Windows game client.
- **Топология:** только одиночная игра. Мультиплеер и Dedicated Server — вне v1.x (v2.0).
- **База кода:** мод строится **форком [Satisfactory Build Calculator](https://github.com/AutoCrafter1223/satisfactory-build-calculator-mod)**
  (MIT), а не с нуля. Вместе с ним в v1.0 приходят интерактивный граф, калькулятор, чтение
  каталога, силовая модель, HUD, хоткеи и локализация.
- **Два рантайма:** игровой процесс (презентационный слой, authority-слой, один исходящий
  канал) и компаньон — наш компонент, внутри которого работают MCP-сервер и vanilla Foreman.
  **Входящего порта у мода нет.**
- **Платформа вперёд своего кода:** конфигурация, хоткеи, персистентность, сторонность сессии
  и реестр контента берутся у SML, а не пишутся заново.
- **Объём v1.0:** ручной контур (планировщик, таблица, интерактивный граф, dashboard,
  персистентность, трекер строительства) плюс текстовый чат. Blueprint Builder и AI Assistant —
  v1.1, рантайм AI-экранов — v1.2, голос — v1.3.
- **Четыре контракта:** `GameCatalog`, `ProductionPlan`, `ScreenDefinition`, `BlueprintRequest`.
  Норматив — JSON-схемы, а не проза; примеры валидируются в CI, типы генерируются.
- **Планировщик:** общая линейная система `A·x = d` при `x ≥ 0`. Деревья, побочные продукты
  и циклы рецептов решаются одним путём, без закрепления ставок игроком.
- **Граница доверия LLM:** модель предлагает, authority-слой валидирует, игрок подтверждает;
  никакого исполняемого кода от LLM.
- **Работа без LLM:** все ручные функции работают при остановленном компаньоне (FR-10).

## Блокирующие проверки до начала работ

| ID | Что проверить |
|---|---|
| Spike S0 | Качество кода форка: прочитать `SBCCalculatorWidget.cpp` целиком, оценить цену адаптации под DAG — до окончательного подтверждения ADR-016 |
| Spike S2 | Доступность движковых модулей `HTTP`/`WebSockets` моду (R-18) |
| Spike S5 | Упаковка компаньона в один исполняемый файл (R-11: `vercel/pkg` заархивирован, Node SEA в Active Development) |
| R-16 | Оценка трудозатрат и состава команды — **не закрыт** |

Риски R-12 (лицензия Ficsit Remote Monitoring) и R-13 (входящий слушатель в игровом процессе),
бывшие блокирующими в v2.0-draft, закрыты — см. §15.1 документа.
