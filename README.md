# FICSIT AI Helper

Мод к Satisfactory и локальный сервис-компаньон, делающие [FICSIT Foreman](https://github.com/StuartMeeks/ficsit-foreman)
инженерным помощником прямо в игре: AI Terminal с переиспользуемыми экранами (Dashboard, Chat,
Notes, Work Orders, Screens), подключаемый планировщик производства и запросы на создание Blueprint.
Экипируемый AI Assistant и HUD — v1.4.

**Статус: только архитектура.** Кода пока нет. Репозиторий содержит проект архитектуры
релизной версии, вынесенный на согласование, — не описание реализованного продукта.

## Главное из архитектуры

- **Целевая платформа:** Satisfactory 1.2, SML 3.12, Windows game client — нативного Linux-клиента у игры нет.
- **Платформа разработки:** Linux, игра под Proton (ADR-033). Мод под Win64 собирается MSVC под wine по официальному
  Linux Setup SML; Windows-машины в команде нет, поэтому проверки упаковки (AC-12) выполняет пилотный тестер.
- **Топология:** только одиночная игра. Мультиплеер и Dedicated Server — вне v1.x (v2.0).
- **Два рантайма:** игровой процесс (презентационный слой, authority-слой) и локальный
  сайдкар: vanilla Foreman плюс тонкий адаптер, через который мод подключается к Foreman
  исходящим соединением. Foreman не форкается и не патчится.
- **UI:** переиспользуемые экранные модули, которые открываются в любом хосте. В v1.0 хост —
  AI Terminal (потребляет 10 MW); в v1.4 те же экраны откроет AI Assistant.
- **Планировщик:** стандартизированная обёртка (`PlanRequest` → `ProductionPlan`, интерфейс
  провайдера и UI плана), в v1.0 — заглушка. Кандидаты провайдера — ядро
  [Satisfactory Build Calculator](https://github.com/AutoCrafter1223/satisfactory-build-calculator-mod) (MIT)
  и линейная система `A·x − s = d` при `x ≥ 0`, `s ≥ 0` (с излишками побочных продуктов),
  которая решает циклы и побочные продукты без LP-решателя, потому что альтернативы выбирает игрок (ADR-028).
- **Платформа вперёд своего кода:** конфигурация, персистентность и состав каталога берутся
  у SML, клавиши — у Enhanced Input игры, а не пишутся заново (ADR-027).
- **Объём v1.0:** AI Terminal; экраны Обзор, Производство, Статистика, Чат с ИИ, Задачи,
  Записки (только текст), Линии, Screens, Настройки; карточки в чате; обёртки Planning и Graph; состояние в сохранении.
  Первым идёт вертикальный срез v0.1 (терминал, Chat, Dashboard). Blueprint Builder — v1.1,
  голос — v1.2, подключение планировщика и UI плана — v1.3, AI Assistant с HUD — v1.4.
- **Публичный API:** все экраны работают через публичный API мода; в v1.1 тот же API открывается
  FicsIt-Networks (Lua, без зависимости от FIN) и другим модам (C++/Blueprint).
- **Отладка без игры:** API работает поверх сменного источника данных (игра, файл `.sav`, запись
  сессии, фикстуры); экраны отлаживаются в отдельном инструменте Screen Lab.
- **Контракты:** `GameCatalog`, `PlanRequest`, `ProductionPlan`, `ScreenDefinition`, `BlueprintRequest`.
- **Ручной паритет:** всё, что может модель (экран, график, заметка, Work Order, чертёж, план),
  игрок делает вручную через UI без LLM — UI и модель вызывают одни и те же операции.
- **Граница доверия LLM:** закрытый набор инструментов без доступа к миру, каждый вызов
  валидируется authority-слоем; никакого исполняемого кода от LLM. **«Модель не изменяет
  игровой мир» — постоянный инвариант, а не объём версии** (ADR-009): строительство, демонтаж,
  рецепты, такт и транспорт остаются только ручными во всех версиях v1.x. Модель управляет
  экранами и библиотекой чертежей, включая удаление чертежей; заметки правит, но не удаляет.
- **Телеметрия v1.0 — в пределах текущей сессии;** персистентная история за 24 ч — v1.1.
  Причина: у Ficsit Remote Monitoring нет лицензии, поэтому модуль пишется без референса.
- **Ассет терминала** разрабатывается в ветви `art/command-center` и входит в объём v1.0.
  Его следствие для контрактов: экранные поверхности меша — 16:9 (ADR-030).
- **Работа без LLM:** ручные функции мода работают при остановленном сайдкаре (FR-10); Work Orders
  требуют сайдкар, но не LLM.

## Блокирующие проверки до начала работ

| ID | Что проверить |
|---|---|
| Spike S2 | Адаптер сайдкара и канал к моду |
| Spike S5 | Упаковка сайдкара: `vercel/pkg` заархивирован, Node SEA в Active Development — выбор делается измерением (R-11) |
| R-16 | Оценка трудозатрат и состава команды — **не закрыт**, главный риск релиза |

R-12 (лицензия Ficsit Remote Monitoring) закрыт отрицательно: файла лицензии в репозитории нет,
код использовать нельзя. Spike S3 от него больше не зависит.

## Лицензия

**GPL-3.0-or-later** — [LICENSE](LICENSE). В [LICENSE.EXCEPTION](LICENSE.EXCEPTION) короткая
оговорка про линковку с игрой и движком.

Мод некоммерческий, и глубоко в лицензии проект не вкладывается. Практически значимо три вещи:

- всё используемое совместимо: MIT, Apache-2.0, MPL-2.0, BSD-3-Clause и GPL-3.0 (SML,
  FicsIt-Networks). Не подходит только EPL-1.0 у Graphviz, который из архитектуры убран и так;
- заимствованный код лежит в `third_party/<project>/` вместе с исходной лицензией и перечнем
  изменений — Factory Spawner и слой данных SBC написаны одиночками, и авторство должно быть видно;
- у Ficsit Remote Monitoring лицензии нет, поэтому его код не берётся. Важно это не юридически,
  а инженерно: референса по структуре данных фабрики у нас нет, телеметрия пишется с нуля.

Внешние моды обращаются к нашему публичному API по имени класса через Blueprint или рефлексию,
без линковки заголовков, поэтому могут быть под любой лицензией (§3.7, ADR-023).
