# Каркас терминала

Первая поставка [D-1 (#33)](https://github.com/kkkingqz/ficsit-ai-helper/issues/33): общие элементы хоста, одинаковые для всех экранных модулей — боковое меню, верхняя полоса статуса, нижняя полоса клавиш, два состояния, забирающие весь экран. Экраны «Статистика» и «Чат с ИИ» — следующая поставка (неделя 2), полный набор состояний — неделя 3.

Источники: `ARCHITECTURE.md` §6.1, §6.3, §6.6–§6.9, §4.2, эскиз [`interfaces/screen-host-and-module.md`](../interfaces/screen-host-and-module.md), концепт `docs/concepts/`. Всё, что концепт показывает, а §6.8 запрещает, здесь не нарисовано — список в разделе 9.

| Макет | Что на нём |
|---|---|
| [`wireframes/frame.svg`](wireframes/frame.svg) | Каркас целиком, 1920 × 1080 при масштабе 100 %, с размерами зон |
| [`wireframes/frame-states.svg`](wireframes/frame-states.svg) | «Нет питания», «инертен», деградация полос |

Подписи интерфейса на макетах — английские и окончательные: это строки для UE Localization, а не заглушки (§6.9, решение King 09.11.2026).

# 1. Опорная сетка и масштаб

Опорное разрешение — **1920 × 1080 при масштабе интерфейса 100 %**. Все размеры ниже даны в этой сетке.

| Зона | Размер | Поведение при изменении размера |
|---|---|---|
| Верхняя полоса статуса | высота 64 | высота фиксирована, содержимое справа сжимается первым |
| Боковое меню | ширина 180 | ширина фиксирована; при высоте < 760 рельс прокручивается, пункты не сжимаются |
| Область экранного модуля | остаток, 1700 × 920 | отдаётся модулю целиком, хост внутри ничего не рисует |
| Нижняя полоса клавиш | высота 56 | высота фиксирована, лишние клавиши уходят в «…» |

- **Масштаб 80–150 %** (§6.9) умножает все три зоны. При 150 % рельс занимает 270 px, полосы — 96 и 84; на 1280 × 720 это оставляет модулю 1010 × 540, и это нижняя граница поддерживаемого. Ниже 1280 × 720 каркас не проверяется.
- **Минимальная ширина модуля — 960 px при 100 %.** Если окно уже, рельс сворачивается в полосу 64 px (только иконки, подпись — во всплывающей подсказке). Это единственное разрешённое изменение каркаса.
- **Плотность информации** (§6.9) на каркас не влияет: она меняет внутренние отступы модулей, а не высоту полос. Иначе каждый модуль придётся верстать под три высоты хоста.

**Экран в мире (render target 16:9, §6.6) — открытый вопрос к Co.** В контексте модуля уже есть признак `bWorldSurface`, то есть модуль про меш знает; про каркас решения нет. Предложение: в мире показывается содержимое модуля и верхняя полоса статуса, а рельс и полоса клавиш не рисуются — ввода там нет, а 180 px рельса на меше съедают девятую часть ширины. Решение нужно до V-1, иначе Gf придётся делать каркас дважды.

# 2. Боковое меню

Состав и порядок — по §6.7. Подписи английские, не длиннее 12 символов, одной строкой; при переводе строка может вырасти, поэтому пункт тянется в высоту, а не обрезается.

| # | Пункт | Экран | Видимость |
|---|---|---|---|
| 1 | OVERVIEW | Обзор | v1.0 |
| 2 | PLANNER | Planning (обёртка) | v1.0 — открывает заглушку «planner not connected» (§6.4) |
| 3 | PRODUCTION | Производство | v1.0 |
| 4 | STATISTICS | Статистика (Dashboard) | **v0.1** |
| 5 | CHAT | Чат с ИИ | **v0.1** |
| 6 | WORK ORDERS | Задачи | v1.0, нужен сайдкар |
| 7 | NOTES | Записки | v1.0 |
| 8 | LINES | Линии | v1.0 |
| 9 | SCREENS | Библиотека экранов | v1.0 |
| 10 | SETTINGS | Настройки | v1.0 |
| — | LOGISTICS | Логистика | **скрыт до v1.5** |

**Правило видимости (§6.7):** пункт нереализованного раздела скрыт, а не заблокирован. Заблокированный пункт обещает то, чего нет, и каждый тестер напишет об этом в отзыве. Единственное исключение — PLANNER: он открывает честную заглушку обёртки, потому что обёртка в v1.0 существует.

**В v0.1 рельс показывает два пункта** — STATISTICS и CHAT. Каркас обязан выглядеть правильно и с двумя пунктами, и с десятью: пункты прижаты к верху, пустое место остаётся пустым, никакой растяжки на всю высоту.

**Геометрия пункта:** слот 76 px; иконка 24 × 24 с отступом 16 сверху; подпись — заглавные, 13 px, по центру, базовая линия на 64 px от верха слота. Десять пунктов занимают 760 px и помещаются в 960 px рабочей высоты без прокрутки.

| Состояние пункта | Как выглядит |
|---|---|
| обычное | прозрачный фон, иконка и подпись приглушённые |
| наведение | фон `surface-raised`, иконка и подпись яркие |
| фокус клавиатуры | рамка 2 px цветом `focus`, фон не меняется — **отличается от наведения**, иначе геймпадом не видно, где ты |
| активный | заливка `accent`, иконка и подпись тёмные, слева полоса 5 px светлее заливки |
| недоступен временно (WORK ORDERS без сайдкара) | обычный вид; недоступность объясняет сам экран, а не рельс |

Последнее правило важно: рельс не гасит пункты по состоянию связи. Иначе игрок видит серый пункт, не знает причины и не может её узнать — а внутри экрана причина помещается целиком.

# 3. Верхняя полоса статуса

Слева направо: блок идентичности (ширина равна рельсу), заголовок текущего экрана, группа связи, группа состояния фабрики.

| Блок | Содержимое | Источник |
|---|---|---|
| Идентичность | `FICSIT` / `FACTORY OS` | константа; версия мода — в «Настройках», в полосе её нет |
| Заголовок | название текущего экрана | модуль (см. раздел 10, пункт 2); шевроны рисует хост |
| TELEMETRY | `LIVE` / `STALE · 42 s` / `OFF` | телеметрия мода (§8.2) |
| SIDECAR | `LINKED` / `OFFLINE` | публичный API мода: состояние сайдкара — свойство API, а не хоста (эскиз интерфейсов) |
| POWER | `1.20 / 1.50 GW` + полоса загрузки | телеметрия |
| ACTIVE LINES | `12 / 12` | телеметрия |
| LOAD | `86 %` | телеметрия |

- **Модель в полосе не участвует** (§6.7): всё это телеметрия. Ни одного значения «по мнению ассистента» здесь нет.
- **Два индикатора связи, а не один.** Телеметрия и сайдкар отказывают независимо: без сайдкара цифры живые, а чат не работает; при провале сбора наоборот. Один общий индикатор врал бы в обоих случаях.
- **Устаревшие данные тускнеют и получают возраст** (`STALE · 42 s`), но не прячутся и не заменяются прочерками: последнее известное значение полезнее пустоты, если видно, что оно старое. Порог — из протокола замеров Gf2.
- **Порядок сжатия при нехватке ширины:** сначала пропадает подпись у LOAD, затем у ACTIVE LINES, затем полоса загрузки у POWER, затем заголовок экрана укорачивается многоточием. Индикаторы связи не сжимаются никогда.
- **Счётчика предупреждений в полосе нет** (§6.8): системы оповещений в v1.0 не существует.

# 4. Нижняя полоса клавиш

Полоса показывает клавиши **текущего экрана**, а не весь набор мода.

| Клавиша | Действие | Чьё |
|---|---|---|
| `Esc` | назад, затем закрыть терминал | хоста, всегда |
| `R` | обновить данные экрана | модуля |
| `F` | фокус на объекте в мире | модуля |
| `C` | экспорт CSV (§6.7) | модуля, где отчёт есть |

- Клавиши объявляет модуль (см. раздел 10, пункт 2); хост рисует их в порядке объявления и всегда добавляет `Esc` последним.
- У «Чата» набор другой: `Enter` — отправить, `Esc` — сначала отмена потока, и только следующим нажатием выход. Отмена потока — требование экрана Chat (§6.3), и она обязана быть первой, иначе игрок выходит из терминала, пытаясь прервать ответ.
- Место счётчика предупреждений справа **зарезервировано и пусто** (§6.7): разметка под него заложена, содержимого в v1.0 нет.
- Клавиши берутся у Enhanced Input игры (ADR-027) и переназначаемы; полоса показывает текущую привязку, а не зашитую букву.

# 5. Состояния каркаса

Для V-1 нужны два, и оба забирают весь экран вместо каркаса.

Оба состояния уже есть в эскизе интерфейсов как `EFicsitAIHostState::NoPower` и `::Inert`, и в обоих `OpenModule` возвращает `false` — то есть каркас с его рельсом и полосами в этих состояниях не рисуется вообще, а не показывается пустым.

**A. Нет питания** (§6.1). Терминал потребляет 10 MW; без питания экран в мире не рендерится, а по `E` открывается только статус. Текст: `NO POWER` / `This terminal requires 10 MW` / `Connect it to a powered grid to use the screens`, мелкой строкой — `Notes, screens and work orders are not lost`. Последняя строка обязательна: игрок, у которого погас терминал, должен сразу знать, что его заметки и экраны целы.

**B. Инертный режим** (§4.2, AC-10). Сессия загружена как мультиплеерная или вошёл удалённый игрок: UI закрыт, связь с адаптером разорвана. Текст: `UNAVAILABLE IN MULTIPLAYER` / `Another player is in this session` / `The mod is inert: screens are closed and the sidecar link is dropped`, мелкой строкой — `Work resumes on its own once remote players leave`. Кнопки «повторить» нет: режим снимается уходом игроков, а не действием игрока.

Обоим состояниям хватает `Esc` в качестве единственной клавиши, и ни одно не предлагает ничего чинить.

Деградации, которые каркас сохраняют (панель C макета состояний): сайдкар отключён, телеметрия устарела. Остальные состояния — «сайдкар не подключён» внутри «Чата» и пустые данные внутри экранов — приходят на неделе 3 вместе с макетами экранов: это состояния модулей, а не хоста.

# 6. Ввод и фокус

- `E` открывает терминал, `Esc` закрывает; пока терминал открыт, ввод игрового мира не проходит.
- Навигация клавиатурой: `Tab` — между зонами (рельс → модуль → полоса клавиш), стрелки — внутри зоны, `Enter` — выбор.
- Геймпад: крестовина повторяет стрелки, бамперы листают пункты рельса. Проверяется на воротах G2 вместе с юзабилити сборки.
- В «Чате» поле ввода перехватывает буквенные клавиши целиком: `R`, `F` и `C` в нём не работают как горячие, и полоса клавиш это показывает. Иначе игрок, печатающий «refresh», обновит экран четыре раза.
- Видимый фокус обязателен в каждой зоне — требование не косметическое: без него геймпадная навигация не проверяется.

# 7. Текст и локализация

- Язык v0.1 — английский, все строки с первого дня через UE Localization (решение King 09.11.2026, §17.1). В разметку текст не зашивается.
- Подписи рельса — заглавные, до 12 символов. Русский перевод длиннее: `WORK ORDERS` → «ЗАДАЧИ» короче, а `SCREENS` → «ЭКРАНЫ» ровно; запас по высоте пункта оставлен под двухстрочный перевод.
- Числа и единицы — по §5.6 (метрические, GW/MW, шт/мин). Разделитель дробной части берётся из локали, а не из разметки.
- Никакого текста в текстурах ассета: проверено 09.11.2026, в `art/command-center` все запечённые надписи английские и декоративные, переводимые строки живут в `content_spec.json → localization.entries`.

# 8. Токены для D-2 (Gs2)

Геометрия каркаса — моя, значения цветов — ваши. Ниже имена токенов, которые каркас использует, и **предварительные** значения, снятые с концепта; окончательные приходят из D-2.

| Токен | Назначение | Предварительно |
|---|---|---|
| `bg-base` | фон экрана | `#0A1724` |
| `surface` | полосы статуса и клавиш | `#0E2032` |
| `surface-raised` | рельс, наведение, клавиша | `#122A40` |
| `stroke` | разделители и рамки | `#1E3D59` |
| `accent` | активный пункт, акценты | `#F5871F` |
| `info` | графики, ссылки, служебные метки | `#2FB8DE` |
| `ok` / `warn` / `stale` | `LINKED`, `LIVE`; предупреждающий акцент; устаревшие данные | `#46C46B` / `#F5871F` / `#E8C33C` |
| `text` / `text-muted` | основной и вторичный текст | `#E6F0F7` / `#8FA9BF` |
| `focus` | рамка фокуса клавиатуры | из D-2, обязан отличаться от `accent` |

Размеры текста каркаса: подпись рельса 13, метка полосы 13, значение полосы 17, заголовок экрана 22. Их тоже стоит завести токенами, чтобы масштаб 80–150 % менялся в одном месте.

# 9. Что намеренно не нарисовано

| Элемент концепта | Почему его нет |
|---|---|
| «Быстрые предупреждения», счётчик алертов | системы оповещений в v1.0 нет (§6.8); место в полосе зарезервировано |
| «Быстрые действия» внизу «Обзора» | меняют мир; вместо них переходы «Открыть в планировщике», «Показать статистику», «Создать задачу» |
| Ползунки оверклока и частоты станков | настройки машин только отображаются (ADR-019) |
| Пункт LOGISTICS | v1.5 (§6.3) |
| Карта фабрики на «Обзоре» | будущие версии (§6.8) |
| Вход в систему, 2FA, автоблокировка в «Настройках» | неприменимо к локальному моду одиночной игры (§6.9) |

# 10. Передача и приёмка

**Gf (V-1, неделя 5)** получает отсюда: размеры трёх зон, сетку рельса, состав и правило видимости пунктов, пять состояний пункта, состав верхней полосы с порядком сжатия, правило владения клавишами и два полноэкранных состояния. Этого достаточно, чтобы собрать каркас на UMG, не придумывая UX по ходу.

**Gs2 (D-2)** получает: список токенов раздела 8, размеры текста и геометрию пункта рельса, полос и клавиши. Компоненты полос и пункта рельса — в дизайн-систему; цвета — ваши.

**Готово, когда** Gf начинает V-1 по этим макетам, а Gs2 строит по ним компоненты D-2. Чек-лист приёмки — из P-7 (Gf2), до начала работы, не после.

**Открытые вопросы — к Co.** Эскиз `interfaces/screen-host-and-module.md` прочитан; каркас с ним сходится в главном (`SizePx`, `AspectRatio`, `bWorldSurface`, `HostState` с `NoPower` и `Inert`, фокус ввода через `RequestInputFocus`). Не сходится в трёх местах:

1. **Заголовок экрана и клавиши модулю объявлять нечем.** В `IFicsitAIScreenModule` есть `GetModuleId`, но нет ни отображаемого имени, ни списка горячих клавиш, а обе эти вещи рисует каркас. Иначе хост будет держать у себя таблицу «id → название», и каждый новый модуль придётся дописывать в хост — ровно та связность, от которой уводит ADR-001. Предложение — два метода модуля:

   ```cpp
   /** Локализованное имя для заголовка каркаса (§6.7). */
   virtual FText GetDisplayName() const = 0;

   /** Подсказки клавиш для нижней полосы, в порядке показа. Esc добавляет хост. */
   virtual TArray<FFicsitAIHotkeyHint> GetHotkeyHints() const { return {}; }
   ```

   где `FFicsitAIHotkeyHint` — действие Enhanced Input (ADR-027) плюс локализованная подпись; букву клавиши полоса берёт из текущей привязки, а не из строки.

2. **Экран в мире:** раздел 1, нужно до V-1.

3. **Порог `STALE`** берём из протокола замеров Gf2 или фиксируем здесь?
