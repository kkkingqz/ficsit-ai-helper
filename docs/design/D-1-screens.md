# Экраны вертикального среза

Вторая поставка [D-1 (#33)](https://github.com/kkkingqz/ficsit-ai-helper/issues/33): два экранных модуля, входящих в v0.1, — «Статистика» (Dashboard) и «Чат с ИИ». Каркас, в котором они открываются, — [D-1-frame.md](D-1-frame.md); полный набор состояний — неделя 3.

Источники: `ARCHITECTURE.md` §6.3, §6.6–§6.9, §7.6, §8.2, §5.6, эскиз [`interfaces/screen-host-and-module.md`](../interfaces/screen-host-and-module.md), концепт `docs/concepts/05`, `06`, `07`.

| Макет | Что на нём |
|---|---|
| [`wireframes/statistics-energy.svg`](wireframes/statistics-energy.svg) | «Статистика», вкладка ENERGY, состояние «данные свежие» |
| [`wireframes/statistics-resources.svg`](wireframes/statistics-resources.svg) | «Статистика», вкладка RESOURCES, состояние «данные устарели, 48 с» |
| [`wireframes/chat.svg`](wireframes/chat.svg) | «Чат с ИИ», ответ потоком и карточки обоих видов |

Подписи интерфейса английские и окончательные — это строки для UE Localization. Числа на макетах согласованы между собой: мощность 1.20 / 1.50 GW в полосе статуса, то же в «Статистике» и в контексте «Чата».

# 1. Общее для обоих экранов

- **Модуль не рисует каркас.** Хост отдаёт область `SizePx`, всё остальное — меню, полосы, заголовок — не его дело (D-1-frame, раздел 1).
- **Данные только через публичный API** (§3.6, ADR-023). Ни один экран не ходит в подсистемы игры напрямую, поэтому оба открываются в Screen Lab на источниках Fixture и Recording.
- **Состояние экрана живёт в состоянии мода** (§10), а не в хосте: выбранная вкладка, окно времени, набор метрик, черновик сообщения чата переживают закрытие терминала.
- **Единицы — §5.6:** `items/min`, `m3/min`, MW и GW. Разделитель разрядов — пробел, десятичный — из локали.
- **Подпись единицы — одна таблица на весь интерфейс.** В API v0 единица приходит перечислением `EFicsitAIUnit`, а не строкой, поэтому «значение перечисления → подпись» нужно ровно одно место, и это место — локализация: иначе `MW` на «Статистике» и `МВт` в карточке чата разойдутся при первом же переводе. Точность берётся из `PrecisionDigits` значения, UI её не придумывает.
- **Телеметрия v1.0 живёт в пределах сессии** (§8.2). Любой график начинается с момента загрузки сохранения, и это сказано на самом экране строкой `Session data only — 24 h history arrives in v1.1`, а не только в документации.

## 1.1 Пять состояний панели — одна сетка

Любая панель обоих экранов живёт в одном из пяти состояний. Сетка одна, чтобы `D-2` делал один компонент, а Fixture проверял один набор (вопрос Gs2-12).

| Состояние | Значение | Ряд | Метка | Возраст |
|---|---|---|---|---|
| `FRESH` | число по `PrecisionDigits` | есть | `UPDATED 2 s AGO`, зелёная | показывается |
| `LOADING` | прочерк, приглушён | пустая сетка без линий | `LOADING`, нейтральная | нет |
| `STALE` | **последнее полученное** число, приглушено | **остаётся**, не обрезается | жёлтая, с возрастом словами | показывается |
| `EMPTY` | прочерк `—` | пустая сетка | `NO DATA`, нейтральная, плюс строка причины | нет |
| `ERROR` | последнее число, если оно было; иначе прочерк | остаётся или пустая сетка | `UNAVAILABLE`, красная | возраст последнего числа |

Четыре правила к сетке:

1. **Прочерк и ноль — разные вещи.** `—` означает «значения нет», `0 MW` — «значение равно нулю», и это свежее число в обычном виде с зелёной меткой. Отсутствие данных никогда не рисуется нулём: иначе погасшая сеть и отсутствующая телеметрия выглядят одинаково, и игрок идёт искать несуществующую поломку.
2. **`LOADING` живёт только до первого снимка** и не дольше `max(3 × SampleIntervalSec, 10 с)`: дальше это `EMPTY` со строкой причины или `ERROR`. Бесконечный скелет — это и есть худший вид ошибки, потому что он ничего не сообщает.
3. **Пояснение ошибки живёт внутри панели**, одной строкой, из кода ошибки API через локализацию. Ни модального окна, ни общей полосы предупреждений: §6.8 запрещает именно это, и отказ одной метрики не должен закрывать экран, на котором работают остальные.
4. **Повтор запроса автоматический**, кнопки `RETRY` нет. Панель сама вернётся в `FRESH` на следующем удачном снимке, и единственное, что об этом говорит, — метка.

Лист состояний с макетами — `D-1-states.md` (неделя 3), там же состояния каркаса и пустая история чата.

# 2. «Статистика» (`dashboard`)

Один модуль с двумя отчётами-вкладками: **ENERGY** и **RESOURCES** (§6.3). Разделять их на два пункта меню не нужно: источник данных один, а переключение вкладкой дешевле навигации.

## 2.1 Шапка отчёта

| Элемент | Поведение |
|---|---|
| Вкладки `ENERGY` / `RESOURCES` | активная вкладка запоминается в состоянии модуля |
| Окно `5 MIN` / `15 MIN` / `60 MIN` | по умолчанию 15; применяется ко всем графикам вкладки сразу, не по одному |
| Метка свежести | `UPDATED 2 s AGO` зелёным; при возрасте больше `max(3 × SampleIntervalSec, 10 с)` — жёлтым, и значения панели тускнеют. Порог считается по каждой метрике отдельно (§8.2, ответ Co-10), поэтому метка панели показывает худшую из её метрик |
| `EXPORT CSV` | кнопка плюс клавиша `C`: один ручной путь, две точки входа |

Окон ровно три, и `24 H` среди них нет до v1.1 — иначе кнопка обещает историю, которой в v1.0 не существует.

## 2.2 Отчёт ENERGY

| Панель | Содержимое | Источник |
|---|---|---|
| `POWER — PRODUCTION AND CONSUMPTION` | два ряда, линия предела сети, легенда с текущими значениями | `power.production`, `power.consumption` |
| `GRID` | стабильность, запас, пик за сессию, число выходов за предел, **состояние предохранителя** (`Fuse OK` / `Fuse tripped` с временем срабатывания), время работы | расчёт по рядам телеметрии |
| Полоса плиток | capacity, consumption, headroom, session peak, generators | телеметрия |
| `GENERATORS BY TYPE` | тип, работает/всего, выдача, загрузка | индекс построек (S3) |
| `FUEL AND BATTERIES` | запас топлива, **заряд батарей в процентах и время до полного заряда или разряда** — что именно, зависит от знака баланса, — полоса заполнения | телеметрия запасов |
| `SELECTED` | карточка выбранного типа или объекта, только чтение | каталог и телеметрия |
| `METRICS` | поиск и выбор рядов для графика | `list_metrics` |

**Выбор метрики — это и есть ручной путь инструмента `query_metric`** (§7.5, правило 1): список в панели `METRICS` — тот же каталог, что видит модель. Единица и точность берутся из API: `unit` и `PrecisionDigits` обязательны в описании метрики, UI их не придумывает (ответ Co-11).

**Не больше четырёх рядов на графике — инвариант, а не вёрстка.** Лимит записан в §7.4 и проверяется `Validator`, поэтому он одинаков для игрока и для модели: `create_screen` с десятью рядами отклоняется там же, где отклонялся бы ручной ввод. В UI пятый выбранный ряд вытесняет самый старый, и об этом говорит подпись, а не молчаливое игнорирование.

**«Время при текущем балансе» — не прогноз.** Подпись `Time left is computed from the current balance, not predicted` стоит на самой панели: иначе игрок прочитает оценку как предсказание, а системы прогнозирования в v1.0 нет.

## 2.3 Отчёт RESOURCES

| Панель | Содержимое |
|---|---|
| Плитки сверху | руды, слитки, детали (добыча/потребление), суммарный запас |
| `EXTRACTION` и `CONSUMPTION` | ряды по ключевым позициям за выбранное окно |
| `BALANCE` | ресурс, производство, потребление, баланс, спарклайн тренда. **Жидкости идут той же таблицей в `m3/min`** (§5.6): единица берётся из метрики, отдельной вкладки под них нет |
| `STOCKS` | запас, изменение в минуту, заполнение хранилищ |
| `SELECTED` | карточка ресурса: категория, запас, потоки, покрытие |
| `STOCK TREND` | динамика запаса выбранного ресурса |

**Колонки «статус» нет.** В концепте рядом с балансом стояли плашки «ДЕФИЦИТ» и «ИЗБЫТОК» — §6.8 их запрещает прямо. Остаётся число баланса со знаком и цветом: `-4` оранжевым читается так же быстро, но ничего не советует и ни о чём не предупреждает.

## 2.4 Экспорт CSV

`C` или кнопка выгружает **данные текущей вкладки за текущее окно**: таблицы — как есть, графики — рядами с отметками времени. Файл кладётся рядом с сохранением, путь показывается подтверждением на 3 секунды. Экспорт — ручная операция без изменения мира (§6.7), модели он не выставляется.

## 2.5 Состояния

| Состояние | Что видно |
|---|---|
| Данные свежие | обычный вид, метка зелёная |
| Данные устарели | метка жёлтая с возрастом, значения тускнеют, графики не обрезаются |
| Телеметрии нет совсем | панели показывают `NO DATA YET` и строку «сбор начинается с загрузки сохранения» |
| Пустая фабрика | таблицы пустые с одной строкой `Nothing is running yet`, графики — пустая сетка без линий |
| Сайдкар отключён | **на «Статистику» не влияет**: телеметрия собирается модом, а не сайдкаром (FR-10) |

Последняя строка — ровно то, что проверяет Fixture «сайдкар недоступен» (§8.5): если «Статистика» в этом наборе опустела, реализация ушла за данными не туда.

## 2.6 Компактная раскладка

В v1.4 тот же модуль откроется в **быстром интерфейсе** — режиме хоста, который открывается клавишей после постройки первого терминала и не зависит от слота и оборудования (§6.2, ADR-035). Экипируемого AI Assistant нет, пресеты остались те же: `slots-3` у терминала, `slots-1` или `hud-compact` у быстрого интерфейса. Порядок выбрасывания при сжатии задаёт дизайн, а не случайный порядок виджетов в разметке, и записан он здесь, чтобы в v1.4 не переделывать вёрстку.

**Что уступает место, по порядку:** `SELECTED` и `METRICS` → таблицы второго плана (`GRID` и `FUEL AND BATTERIES` на `ENERGY`, `STOCKS` и `STOCK TREND` на `RESOURCES`) → второй график вкладки → сгруппированная таблица. Полоса плиток, главный график активной вкладки и метка свежести не выбрасываются никогда: без них экран перестаёт отвечать на вопрос, с которым его открыли.

**Опорный компактный размер — 1010 × 540** (прогон S8, вопрос Gs2-12). На этой высоте помещаются три полосы, и делятся они так:

| Полоса | Высота | Содержимое |
|---|---|---|
| Плитки | 72 | `ENERGY`: production, consumption, headroom, **fuse**, **batteries**; `RESOURCES`: добыча, потребление, баланс, суммарный запас |
| Главный график | ≈ 260 | один график активной вкладки, легенда с текущими значениями внутри поля графика |
| Сгруппированная таблица | ≈ 170 | `ENERGY` — `GENERATORS BY TYPE`; `RESOURCES` — `BALANCE` |

Состояние предохранителя и заряд батарей **не уступают место вместе со своими таблицами, а переезжают в плитки**: это одно значение и один признак, а в терминале их требует V-02, и терять их при сжатии нельзя. Остальное содержимое `GRID` и `FUEL AND BATTERIES` на этом размере не показывается.

**Таблица прокручивается внутри панели, заголовок остаётся на месте** (предложение Gs2 принято). Если на таблицу остаётся меньше 120 px, она уступает место целиком и график забирает её высоту: две видимые строки из двадцати хуже, чем честное отсутствие таблицы с подписью, где её смотреть.

Приёмка V-02 идёт на терминале в раскладке `slots-3`; компактная раскладка — задача v1.4 и в объём v0.1 не входит.

# 3. «Чат с ИИ» (`chat`)

## 3.1 Поток разговора

- Сообщения двух авторов: `OPERATOR` и `FICSIT AI`, время справа, цветная полоса слева. Длинные ответы не сворачиваются: прокрутка дешевле, чем «показать ещё».
- **Ответ идёт потоком**, рядом с индикатором — видимая кнопка `STOP` и строка `Streaming…  Esc stops the answer`. Клавиша в строке — текущая привязка действия «назад», а не зашитая буква: перехват идёт через `HandleBackAction()` (ответ Co-25). Кнопка обязательна: ручной путь не должен существовать только в виде горячей клавиши, и V-03 чек-листа Gf2 проверяет именно её. `Esc` работает лестницей из трёх ступеней (D-1-frame, раздел 4): поток → фокус → выход, и ни на одной ступени набранный текст не теряется.
- **История живёт у Foreman** (§10: переписка — в его БД, привязана к playthrough, сопоставленному с `saveId`), а не в состоянии мода и не в сохранении. Экран её только читает через адаптер. Отсюда три следствия для UX: при переоткрытии терминала с поднятым сайдкаром история восстанавливается; без сайдкара прошлая переписка недоступна, а уже показанные сообщения остаются на экране до закрытия; черновик неотправленного сообщения живёт в памяти модуля и в сохранение не пишется.
- Прошлые сообщения остаются авторским текстом игрока (§7.3) и в контекст попадают размеченными как данные.
- Поле ввода: до 2000 символов, `Enter` — отправить, `Shift+Enter` — перенос строки. Пока фокус в поле, `R`, `F` и `C` набираются как буквы, и нижняя полоса показывает именно чатовский набор клавиш.

## 3.2 Карточки в ответах

Карточка — **один виджет из белого списка** (§7.6), тот же, что на «Статистике» и в редакторе Screens. Видов два, и они различаются на глаз:

| Вид | Метка | Что показывает |
|---|---|---|
| Карточка со ссылкой | `LIVE SOURCE`, зелёным | живые значения мода по `source`; модель не может ошибиться в цифрах |
| Карточка с данными | `ASSISTANT ESTIMATE`, оранжевой рамкой | значения самой модели: «до/после», требования, прикидки |

Метка — не украшение, а граница ответственности: без неё прогноз модели неотличим от показаний телеметрии. HTML от модели не принимается ни в каком виде (ADR-005).

## 3.3 Правая колонка

| Панель | Содержимое | Откуда |
|---|---|---|
| `FACTORY CONTEXT` | эффективность, загрузка, мощность, активные линии | телеметрия, не модель — так и подписано |
| `RELATED WORK ORDERS` | задачи Foreman со статусами | REST Foreman через адаптер; создаются и правятся вручную на экране Work Orders |
| `ASSISTANT` | статус, модель, задержка, токены | адаптер; **токены показываются, только если Foreman их отдаёт** (§6.8, проверка в S2) |

**Панели «Рекомендуемые действия» нет.** В концепте она занимала треть правой колонки; §6.8 отправляет рекомендации в будущие версии вместе с системой оповещений. Её место занял контекст фабрики — те же данные, но без совета.

## 3.4 Шаблоны запросов

Четыре чипа под полем ввода: `Find the bottleneck`, `Explain this metric`, `Power use this session`, `What changed in 15 min`. Шаблон **только подставляет текст в поле** и ничего не отправляет (§6.8: «быстрые команды ассистента» → «шаблоны запросов»). Подпись `Templates only prefill the input — nothing is sent until you press Send` стоит на экране: игрок должен видеть, что нажатие чипа не разговаривает с моделью за него.

## 3.5 Состояния

| Состояние | Что видно |
|---|---|
| Сайдкар не подключён | вместо поля ввода полоса `Assistant unavailable — the sidecar is not connected`, ниже строкой: `Statistics, Notes, Screens and Lines keep working` (FR-10) и короткая инструкция, как поднять сайдкар (V-03). **Прошлая переписка не читается** — она у Foreman; уже показанные сообщения остаются на экране |
| Ответ прерван игроком | сообщение остаётся как есть с пометкой `Stopped`, ничего не исчезает |
| Ошибка адаптера | блок ошибки с машиночитаемой причиной и кнопкой `Retry`; текст ошибки не выдаётся за ответ модели |
| Лимит частоты (§7.4) | строка `Too many requests — try again in 20 s` под полем ввода, поле не блокируется |
| Пустая история | приветственный блок с тремя шаблонами и одной строкой о том, что модель не меняет мир |

Последнее стоит сказать прямо в пустом состоянии: игрок, впервые открывший чат, должен сразу знать границу — модель строит экраны и заметки, но не строит и не перестраивает фабрику (ADR-009).

# 4. Что из концепта не нарисовано

| Элемент концепта | Решение |
|---|---|
| `ПРЕДУПРЕЖДЕНИЯ (2)` внизу отчёта по энергии | системы оповещений в v1.0 нет (§6.8) |
| `КЛЮЧЕВЫЕ ПОКАЗАТЕЛИ` с плашками «ВНИМАНИЕ» | то же; сами показатели остались, ярлыки убраны |
| `РЕКОМЕНДУЕМЫЕ ДЕЙСТВИЯ` на обоих отчётах и в чате | будущие версии (§6.8) |
| Ползунок `ОВЕРКЛОК / АНДЕРКЛОК` в карточке объекта | настройки машин только отображаются: строка `Clock 100%` и подпись `Machine settings are read-only` (ADR-019) |

# 6. Передача

**Gs2 (D-2).** Экраны просят у дизайн-системы компоненты сверх базовых: плитка метрики, график ряда с легендой и отметкой свежести, таблица с числовой колонкой и спарклайном, полоса заполнения, карточка объекта «ключ — значение», блок сообщения чата, карточка-виджет с меткой происхождения, чип шаблона, сегментированный переключатель окна. Токены — из раздела 8 D-1-frame.

**Gf (V-1) и Co2 (V-5, V-6).** Разметка панелей и порядок приоритетов при сжатии — здесь; данные и ручной путь — за вами. Один contract-facing момент: панель `METRICS` строится по ответу `list_metrics`, поэтому поля `id`, `name`, `unit`, `hasSeries`, привязка к линии или предмету нужны все — без `unit` плитки и оси подписывать нечем.

**Готово, когда** Gf начинает V-1, а Gs2 — компоненты D-2 по этим макетам. Приёмка — по чек-листу Gf2 из P-7.

**Вопросы Co3-1…Co3-4 закрыты** ответами Co-8…Co-11: методы `GetDisplayName` и `GetHotkeyHints` приняты, экран в мире остаётся без рельса и полосы клавиш, порог устаревания считается по `SampleIntervalSec`, `unit` и `PrecisionDigits` обязательны, лимит в четыре ряда стал инвариантом §7.4. **Co3-9 закрыт** ответом Co-25: отмену потока модуль перехватывает через `HandleBackAction()`, отдельного метода под клавишу не будет. Открытых вопросов по экранам нет ([docs/team/questions/Co3.md](../team/questions/Co3.md)).
