# King — задачи этапа 1

**Профиль:** владелец продукта. **План этапа:** [PLAN-v0.1.md](../PLAN-v0.1.md). **Milestone:** [v0.1](https://github.com/kkkingqz/ficsit-ai-helper/milestone/1).

## Роль

Решения на воротах W, G1 и G2, тестовые сохранения, имена модов в SMR, набор альфа-тестеров и форма отзыва.

## Решения по срокам

| Когда | Решение |
|---|---|
| До недели 1 | Закрытая или открытая альфа; провайдер LLM по умолчанию для тестеров |
| Неделя 1–2 | Тестовые сохранения (P-5); имена модов в SMR (P-6); **пилотный тестер с Windows и игрой** — нужен к неделе 3 (резервная проверка S8) и обязательно к неделе 8 (архив сайдкара до G2). Устройство для Proton не нужно: это основная платформа команды (ADR-033) |
| Неделя 3, ворота W | ADR-032: веб-экраны или UMG; что делать, если не работает только Proton |
| Неделя 5, ворота G1 | Переход к сборке v0.1; состав телеметрии v0.1 |
| Недели 6–9 | Набор 10–30 альфа-тестеров, форма отзыва |
| Неделя 9, ворота G2 | Выпуск альфы; канал раздачи (SMR или GitHub Releases) |

## С кем стыкуется

- Co — предлагает решения на воротах и записывает их в `ARCHITECTURE.md`
- Пилотный тестер — единственная Windows-машина проекта: AC-12 и V-08 проверяются только у него (R-27)
- Gf2 — проверяет критерии перед G1 и G2
- Co3 — материалы альфы

## Правила

- Каждый PR в мод проходит ревью Co; для задач Gf это обязательная часть плана.
- Перед началом спайка — чек-лист Gf2 из P-7; работа считается готовой по нему, а не по ощущению.
- Решения по итогам спайков записываются в `ARCHITECTURE.md` на воротах (пишет Co, утверждает King).
- Задержка больше чем на день по задаче критического пути — сразу сообщить Co и King.
