# Зачем

Новая сессия роли должна продолжить работу, не перечитывая `KICKOFF.md` и `ARCHITECTURE.md` целиком (решение King 10.11.2026, `ARCHITECTURE.md` §17.1). Для этого у каждой роли есть краткий файл состояния: `docs/team/state/<Роль>.md`.

Порядок при продолжении работы: `AGENTS.md` → свой файл состояния → текущая задача → только нужный раздел архитектуры.

# Правила

- **Файл ведёт сама роль** и коммитит его прямо в `main`, как свой файл вопросов. Чужой файл состояния никто не правит.
- **Объём — до 2000 знаков.** Это сводка, а не журнал: устаревшее удаляется, а не дописывается снизу.
- **Решений в файле нет, только ссылки.** Источник истины прежний: `ARCHITECTURE.md`, задачи milestone, журналы версий контрактов. При расхождении файл состояния неправ, и его правят.
- **Обновляется в трёх случаях:** задача закончена, работа передана другой роли, изменилась зависимость. И всегда перед тем, как сессия заканчивает работу.
- **Дата в первой строке обязательна.** Файл старше текущей задачи — подсказка, а не факт: сверь с задачей milestone и `git log`.
- Вопросы другим ролям сюда не пишутся, для них есть [questions/](../questions/README.md). Здесь только номера тех, что блокируют.

# Шаблон

```markdown
# <Роль> — состояние на <дата>

**Сейчас:** <задача, номер в milestone, ветка>

**Последний результат:** <что закончено, ссылка на PR или коммит>

**Блокирует меня:** <номера открытых вопросов и PR, или «ничего»>

**Ждут меня:** <ревью, ответы, передачи другим ролям>

**Решения, на которых стою:** <ADR и разделы, без пересказа>

**Дальше:**

1. …
2. …
3. …
```
