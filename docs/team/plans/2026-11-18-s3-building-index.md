# S3 — индекс акторов построек

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** единственный индекс постоянных акторов построек для последующей выборки телеметрии, с первоначальным чтением и обновлением по событиям.
**Architecture:** GameFacade/BuildingIndex хранит ключ, класс, положение и слабую ссылку; изменяемые производственные значения туда не попадают. После первоначального чтения AFG subsystem используются mBuildableAddedDelegate/mBuildableRemovedDelegate. Владелец запускается только в активной одиночной сессии.
**Tech Stack:** UE 5.3/C++, SML 3.12, CL 517554, Win64 Shipping/Proton.
**Spec:** ARCHITECTURE.md §5.7, §8.2; tests/test-plan/spikes-checklist.md §3.2.

## Границы и принятые решения

Это продолжение утверждённого S3 (#11), по поручению King работать самостоятельно. Каталог остаётся отдельным PR #73; индекс основан на main и не зависит от его слияния.
Рассмотрены первоначальное чтение + события и повторный полный обход; второй вариант противоречит §8.2. Подписка на каждого актора отдельно увеличивает число подписок, хотя у игрового subsystem есть нужные события. Выбран первый вариант.

В этой поставке — постоянные акторы из FGBuildableSubsystem. Их кандидат buildingId — GetPathName(), однажды при добавлении. Пуловые/конвертируемые лёгкие акторы отбрасываются: они не представляют устойчивую постройку. На Save B 145 таких путей менялись между загрузками. Индексы FGLightweightBuildableSubsystem могут переиспользоваться; нельзя объявлять их устойчивыми ключами без проверки и решения R-19. Полный пункт устойчивости на трёх сохранениях этим PR не закрывается. Вопрос Co/Gf — Gs-119.

Линии остаются в существующем FFicsitAILineRegistry. Индекс может получить ссылку на него при старте, читает принадлежность при выдаче записи и удаляет привязку при удалении постройки. Отдельной копии обратного отображения линий не создаётся. Временный демонтаж/переход в инертный режим не считается массовым удалением построек из линий.

## Global Constraints

- Правки кода только GameFacade/BuildingIndex/ в зоне Gs. Регистрация subsystem в WorldModule — только по Gs-120/согласованию Co.
- Типы AFG/UFG остаются в GameFacade.
- UObject и индекс доступны только на GameThread; слабые ссылки не удерживают акторов.
- Первоначальное чтение однократно; события до его окончания не теряются.
- Повторные добавления/удаления идемпотентны; удаление прежнего объекта не удаляет заменивший его объект.
- Ключи сравниваются с учётом регистра. Сборщик получает готовый идентификатор из индекса.
- После подготовки владелец выключает tick. Ожидание инициализации ограничено.
- Инертный режим не читает и не отдаёт данные. Завершение мира снимает подписки.
- Shader workers 5; собственный SDK .gs-s3-sdk-EUOjne, чужие SDK не изменять.

## Review Focus

- Два разных объекта с одним ключом: старая remove-событие сохраняет новую запись (тест хранилища).
- Переименование/повторная регистрация одного объекта: старая запись не остаётся (тест хранилища).
- Пуловые лёгкие акторы не попадают в индекс и не разрушают линии (проба в мире).
- Повторный Start/Stop и выгрузка мира не оставляют подписок и записей (проба в мире).
- Инертный режим и повторное событие удаления не меняют сохранённые линии (тест хранилища + проба в мире).
