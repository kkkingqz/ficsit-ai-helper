# Правило

**Каждый коммитит только файлы своей зоны.** Нужен чужой файл — не правь его, а задай вопрос владельцу: [questions/](questions/README.md).

Три категории путей, и больше никаких:

1. **Своя зона** — правишь свободно.
2. **Чужая зона** — не трогаешь вообще. Даже опечатку: это вопрос владельцу, а не правка.
3. **Общие файлы** — перечислены ниже поимённо. В них можно добавить или поправить **только свою строку**. Чужие строки не переписывать, не переставлять, не переформатировать.

Один PR не трогает зоны двух людей. Если изменение требует двух зон — два PR, и второй после первого.

**Исключение — делегирование** (решение King 10.11.2026). PR может менять файлы чужой зоны, если владелец дал на это письменное согласие:

- согласие — ответ владельца в его файле вопросов, где названы задача или PR и пути;
- ссылка на ответ стоит в описании PR;
- свою часть владелец ревьюит сам, по правилам записи ревью из `AGENTS.md` §6;
- согласие действует на один PR и на названные пути, а не на зону вообще.

Первый случай — [PR #40](https://github.com/kkkingqz/ficsit-ai-helper/pull/40): Gf перенёс интерфейсы в `FicsitAIApi/` по вопросу Gf-6 и ответу Co-36. Автоматической проверки зон в CI пока нет: она отложена до ворот W.

# Рабочая копия на сессию

**У каждой роли своя рабочая копия** (решение King 09.11.2026). Общее рабочее дерево было причиной того, что сессии мешали друг другу, и соглашением эту причину не убрать.

| Путь | Что это |
|---|---|
| `~/Projects/ficsitai` | **Узел.** Ветка `main`, ничего не правится руками: только `git fetch` и `git pull`, чтобы посмотреть собранное состояние |
| `~/Projects/ficsitai-<роль>` | Твоя рабочая копия на ветке `work/<роль>` |

Копии сделаны через `git worktree`, поэтому объекты общие: каждая стоит около 21 МБ при репозитории в 535 МБ. Если твоей копии нет, её создаёт один раз:

```bash
/usr/bin/git -C ~/Projects/ficsitai worktree add -b work/<роль> ~/Projects/ficsitai-<роль> origin/main
```

**Как работать:**

0. **`git` вызывай полным путём `/usr/bin/git`:** симлинк в `~/.local/bin/git` из рантайма Codex перехватывает PATH и роняет любую сетевую операцию (`fatal: remote helper 'https' aborted session`), хотя локальные команды у него работают. Подробности — `AGENTS.md`, раздел 10.
1. Свежий `main`: `/usr/bin/git fetch origin && /usr/bin/git rebase origin/main` в своей копии.
2. **Документы** можно отправлять прямо в `main`, пока это fast-forward: `git push origin HEAD:main`. Отказ означает, что кто-то успел раньше — тогда `git fetch origin && git rebase origin/main` и снова.
3. **Код** идёт через задачную ветку и PR по правилам `CONTRIBUTING.md`: `git switch -c mod/s1-terminal origin/main` в своей же копии, затем PR и ревью.
4. Одну ветку нельзя держать в двух копиях одновременно — и это хорошо: так ветка не уедет под чужими руками.

**Что всё равно нельзя,** потому что бьёт по общим объектам или по узлу:

| Нельзя | Почему |
|---|---|
| Править файлы в `~/Projects/ficsitai` | это узел, его дерево — собранное состояние, а не чьё-то рабочее |
| `git worktree remove` чужой копии | удалит чужую незакоммиченную работу |
| `git branch -D work/<чужая роль>`, `git push --force` в `main` | снесёт чужую историю |
| Коммитить чужие пути | зоны выше; это правило не отменяется своей копией |

**Гигиена внутри своей копии** осталась прежней, хотя теперь ошибка стоит дешевле: `git add` с конкретными путями, `git diff --cached --name-only` глазами. `git add -A` в своей копии допустим, но только если ты посмотрел `git status` и понимаешь каждую строку.

**Подпись роли.** Все коммиты идут от одной идентичности (`Bodya <kkingqz@gmail.com>`), поэтому по автору не видно, кто работал. В сообщение коммита добавляется строка `Роль: <Роль>`.

**Что бывает без этого — случай 09.11.2026.** Коммит `dfe7fad` «docs: CLAUDE.md — инструкции для сессий проекта» сделан Co через `git add -A` в общем дереве и забрал чужую несохранённую работу: **весь P-2 Co2** (`CONTRIBUTING.md`, шаблоны задачи и PR, каркас каталогов с `README.md` и `.gitkeep`) и **макеты Co3** (`docs/design/wireframes/frame.svg`, `frame-states.svg`). Ничего не потерялось — всё лежит в `main`, — но в истории работа двух человек приписана третьему, а их собственных коммитов за эти поставки нет. Историю не переписываем: `main` общий, а `--force` в него запрещён здесь же. Поэтому факт записан тут, и это цена, которую уже заплатили: правило про конкретные пути и строку `Роль:` появилось после него, а не до.

# Чего нельзя было в общем клоне

История вопроса: до 09.11.2026 все сессии работали в одном дереве, и запреты были такими:

| Нельзя | Почему |
|---|---|
| `git add -A`, `git add .`, `git commit -a` | заберёт чужие недоделанные файлы в твой коммит |
| `git stash` | спрячет чужую работу, и человек не поймёт, куда она делась |
| `git reset --hard`, `git checkout -- .`, `git clean` | удалит чужое без следа |
| `git checkout <ветка>`, `git rebase` в общем клоне | выдернет пол из-под другой сессии посреди работы |

Что делать вместо:

1. `git status` перед коммитом. В выводе будут чужие изменения — это нормально, их не трогают.
2. `git add <конкретные пути>` — только свои. Потом `git diff --cached --name-only` и глазами проверить, что чужого нет.
3. **Подпись роли.** Все коммиты идут от одной идентичности (`Bodya <kkingqz@gmail.com>`), поэтому по автору не видно, кто работал. В сообщение коммита добавляется строка `Роль: <Роль>` — иначе ревью и разбор истории превращаются в угадывание.

**Сильное решение, если мешать друг другу продолжим:** своя рабочая копия на сессию — `git worktree add ../ficsitai-<роль> <ветка>`. Тогда рабочие деревья не пересекаются вообще, каждый сидит на своей ветке, и общий остаётся только `origin`. Решает King; пока работаем соглашением.

# Если правило мешает

Оно и должно мешать — в этом смысл. Но если зона размечена неудобно или твоя работа честно требует чужого файла, это не повод тихо его править: напиши вопрос в [questions/](questions/README.md), а срочное — прямо в задачу milestone или Co и King. Разметку зон правит Co, и она не священна.
