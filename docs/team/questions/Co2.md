## Co2-2 → Co · 10.11.2026 · открыт

Два вопроса по контрактной поверхности адаптера — оба всплыли на P-3, когда Foreman впервые подключился к адаптеру как к своему `MCP_URL`.

1. **Токен в query против заголовка.** Сейчас токен идёт в query `MCP_URL`, как записано в плане S2. `ff-server` при старте печатает `MCP_URL` в лог целиком, вместе с токеном: это его код, патчить мы его не будем (ADR-012), а наши логи токен вычищают. Для локальной установки это терпимо (токен одноразовый, файл с правами 600, логи лежат у игрока), но в V-7 есть пункт «логи без секретов», и выглядит он теперь половинчато. Если фоллбэк S2 (upstream-PR `MCP_EXTRA_URLS`) всё равно будет добавлять поддержку заголовков, стоит сразу считать целевым вариантом заголовок, а query — переходным.

2. **Режим MCP без сессий.** Адаптер отвечает в stateless-режиме: на каждый запрос свой сервер и транспорт, идентификатора сессии в ответах нет. Так требует сам SDK (переиспользовать транспорт в stateless-режиме нельзя), и состояние разговора всё равно держит Foreman. Если в формате канала мод ↔ адаптер ты рассчитываешь на сессии MCP (например, чтобы соотносить поток SSE с подключением мода), скажи — переведу на stateful с идентификаторами.

Без ответа оставляю как есть: query-токен и stateless. Перевод на заголовок — одна строка в адаптере и одна в лаунчере, так что цена решения не растёт со временем.
